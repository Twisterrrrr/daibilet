# Venue editorial generation rules (Daibilet)

Правила для SEO/глянцевых текстов площадок (`seoSections`, FAQ, heroLead, meta).
Цель: коммерческий интент daibilet.ru, не брошюра и не клон Википедии.

## Workflow: owner дает базу, агент - редактор

1. Owner присылает черновик (YAML/список полей) по slug.
2. Агент **сам** правит как редактор и кладет в `apps/web/src/lib/venue-editorial-packs.ts` (+ hours в `venue-opening-hours.ts` при необходимости).
3. Owner не обязан присылать «идеальный» финал: опечатки, битые URL, тире, ложные «без наценки», шаблонные H2 и лишний 18+ - зона агента.

Что агент правит обязательно:
- дефисы `-` вместо длинных/средних тире;
- валидные `sources` / `website` (без склеек вроде `site.rufor-visitors`);
- `phone: null` вместо «нет»;
- грамматика и падежи («Иваном Цветаевым», не «Иван Цветаевым»);
- честная коммерция без обещаний контракта, которого нет;
- уникальные H2 под тип площадки;
- trust-маркеры года / «сверяйте при выборе билета»;
- age-бейджи только если это правда для площадки в целом.

## Коммерция вместо «брошюрности»

- Писать через призму транзакции: сеансы, слоты, электронный билет, афиша на этой странице.
- Триггеры «без наценки» / «официальный партнер» - только при реальном контракте.
- Безопасная формула по умолчанию: «актуальные даты и цены при выборе билета в системе бронирования».
- Не конкурировать с энциклопедией длинной архитектурой/историей ради истории.

## H2 по типу площадки (не AI-тургид)

Запрещён одинаковый скелет «Почему стоит прийти / Как добраться / Правила» на всех страницах.

| Тип | Ориентиры H2 |
| --- | --- |
| Театр / концерт / клуб | `{Название} - афиша, выбор мест и билеты`; специфика залов / гастро-формат вечера |
| Музей / выставка | Экспозиция и правила посещения по сеансам; скрытые детали / уникальная фишка залов |
| Парк / открытая локация | Маршрут: что смотреть в первую очередь; лайфхаки и логистика |

## Trust и актуальность

- Не фиксировать хрупкие цифры без маркера года («депозит 2000», «вход бесплатный» как абсолют).
- Формулы: «По состоянию на 2026 год…», «актуальную стоимость и льготы проверяйте при выборе билета», «правила площадки могут меняться».

## Техгигиена YAML / копирайт

- Только обычный дефис `-` (не длинное/среднее тире).
- `phone: null` вместо `phone: нет`.
- Источники - валидные URL, без склеенных битых строк.
- SEO Title черновик: `{Название} в {Город} - купить билеты, актуальная афиша на {Год}, цены и отзывы на daibilet.ru`.

## UX на PDP (не путать с SEO-текстом)

- Не добавлять сайдбар «Быстрое действие» и hero-кнопку «Выбрать событие» ради скролла к афише.
- CTA в hero / sticky: только реальный admission («К билетам»), иначе «В мой день» / контакты + карта.
- `heroLead` - атмосферный премиум-лид, не прайс-лист из одного предложения.
