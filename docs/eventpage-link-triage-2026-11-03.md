# EventPage: простые связи и очередь вопросов — 2026-11-03

Срез по `eventpage-eventid-matrix-2026-11-03.csv`. Все 5 657 строк получили triage bucket в соседнем `eventpage-link-triage-2026-11-03.csv`. Классификация не меняет БД, публичные URL или SEO.

## Порядок работы

1. Сначала закреплять очевидную идентичность: один Event ID → одна локальная EventPage. Несколько слотов одного Event остаются на этой странице.
2. Отдельно применять уже подтверждённые решения владельца, например `KEEP_SEPARATE_PDP`.
3. Все повторяющиеся точные названия между городами/площадками, collision candidates, существующие `pdp_key` и специальные архивные решения держать в очереди проверки.
4. Исторические URL без точной связи с Event ID оставить fallback, пока не будет проверенного соответствия.
5. Гастрольные страницы связывать общей `tourGroupId` только после проверки; при этом локальные PDP остаются отдельными, с переходами между городами.

## Результат первичного разбора

- **3 450 Event ID** — исходно простые по матрице: точное название не повторяется на другой площадке/в другом городе, нет флага коллизии и существующего `pdp_key`. Production-проверка генератора slug выявила 4 конфликтующих slug у 8 событий; они переведены в review. В чистом пакете осталось **3 442 Event ID**. Рекомендуемая цель — `event:<Event ID>` (это рабочий ключ сопоставления, не фактический ID записи EventPage).
- **8 Event ID** — владелец уже подтвердил отдельные страницы. Их можно ставить в прямую очередь создания/привязки, не открывая решение о слиянии заново.
- **825 Event ID** — вопросы к идентичности/связям: 816 из первичного разбора плюс 9 slug-конфликтов; повторы названий по городам и площадкам, 222 collision candidate, 6 существующих `pdp_key`, архивные и прочие специальные решения. Внутри могут пересекаться несколько причин; CSV показывает первую очередь/основание на каждой строке.
- **78 текущих URL** — Event ID не найден.
- **1 305 исторических URL Search Console** — связь с PDP не подтверждена. В выгрузке один из этих URL содержит Event ID, но он помечен отдельным решением на проверку; точное совпадение ID само по себе не отменяет это решение.

Для одного Event ID в матрице есть две URL-версии. Их нельзя превращать в две EventPage: после проверки alias обе должны вести к одной локальной странице.

## Production-проверка простого пула

Read-only запрос подтвердил, что в production сейчас `EventPage` и `EventPageEvent` пусты: 0 страниц и 0 связей. Все 3 450 исходных простых Event ID найдены в production `Event`. Среди 3 441 slug-уникальных кандидатов: 2 548 событий со статусом `READY`, 49 — `REVIEW`, 844 — `HIDDEN`; у 2 533 есть будущие активные сеансы, у 2 530 — активные офферы. Статусы, сеансы, офферы и рассчитанные slug сохранены в `eventpage-simple-targets-2026-11-03.csv`; список межгородских кандидатов для проверки `tourGroupId` вынесен в `eventpage-tour-group-review-2026-11-03.csv`.

Пять конфликтующих slug-групп вынесены из чистого пакета: `LRK Trio` / `ЛРК ТРИО`, «Вечеринка Ретро FM с группой Чингис Хан» (Екатеринбург/Челябинск), «Чёрный Кофе», «Антон и Виктория Макарские — Живая встреча» и Макс Евдокимов (Омск, Новосибирск, Абакан, Новокузнецк). Они требуют локального slug/identity review. Там, где подтверждён общий гастрольный продукт, локальные страницы следует связать через `tourGroupId`; автоматически связь не назначалась.

Production-записи не создавались. `event:<Event ID>` и slug в CSV — подготовленные цели, не фактические записи EventPage.

## Что означает «простой»

Это безопасный кандидат на самостоятельную EventPage, не опубликованная или созданная запись. Фактические записи EventPage не создавались. Если у названия есть другие города/площадки, оно исключено из простого пула, даже если похоже на гастроли: такая группа требует явного подтверждения и `tourGroupId`.

Проверенные записи владельца `KEEP_SEPARATE_PDP` вынесены отдельно от вопросной очереди, потому что решение «не объединять» уже принято. Их target EventPage ещё нужно создать или установить.

## Редакционные рерайты

В triage к строкам добавлены имена найденных файлов-источников по точному Event ID. Эти ссылки показывают, где хранится текст; они **не доказывают** его применение в production. Неполные/укороченные ID и совпадения только по названию остаются несопоставленными.

Никаких правок EventPage, production DB, canonical, sitemap, redirect или публичных страниц не выполнялось.
