## Что установлено (проверено на живом сайте)

Причина «92 дублей» и «97 совпадающих путей на 246 записей» — **НЕ дубликаты записей
и НЕ формат URL**. Это рукописный `canonicalPath`.

`apps/web/src/lib/sitemap-data.ts:309`:
```ts
const path =
  venue.canonicalPath ||        // ← приоритет у canonicalPath
  venueHref({ id: venue.id, slug: venue.slug, name: venue.name });
```

- `Venue.slug` уникален по построению (хеш от ID), но **публично не используется** —
  адрес с хешем отдаёт 404, хвост не резолвится роутом;
- `canonicalPath` заполняется вручную и **не проверяется на уникальность**;
- поэтому 18 разных «Руки Вверх» из 18 городов получили один путь `/venues/ruki-vverh-bar`.

Подтверждено на live:
```
/venues/ruki-vverh-bar  → 200, отдаёт «Руки Вверх Бар в Ухта»
/venues/harat-s-pub     → 200, отдаёт «Harat's Pub в Тверь»
/venues/muzey-v-temnote-sensorium-642c67fd…  → 404   (slug-хвост не работает)
```

**Это потеря индексируемых страниц, а не косметика:** остальные 17 площадок не имеют
собственного адреса, их города не получают площадку в хабах.

## Задача 1 — инвентаризация (read-only, до любых правок)

1. Сколько записей имеют **непустой `canonicalPath`**, и сколько из них индексируются.
2. Полный список **групп с одинаковым `canonicalPath`**: путь, ID всех записей, slug,
   город, `pageStatus`, источник, число связанных событий.
3. Отдельно раздели группы:
   - **один город** — реальные дубли, их можно слить;
   - **разные города** — разные площадки, слияние ЗАПРЕЩЕНО.

Ориентир из `r4-collision-paths.csv`: 78 путей, 60 смешивают города; из них
37 — пара в одном городе, 41 — пара в разных, 19 — по 3–18 записей.

**Результат — в `docs/research/canonical-path-audit-20261002/` (в git, не в scratch).**

## Задача 2 — план разведения, без применения

Для каждой группы предложи уникальный путь. Два варианта:

- **город в slug:** `dom-kultury-ekaterinburg` — читаемо, SEO-полезно, согласуется
  с действующим стандартом `moscow-muzey-garazh`;
- **ключ в конце:** `dom-kultury-69e9b` — гарантированно уникально, но нечитаемо.

Мой выбор: первый, а для универгальных названий оставлять суффикс. Но решение
за owner — дай цифры по обоим вариантам.

**Обязательно в плане:**
- таблица `старый путь → новый путь` для **301**;
- не менять пути у записей, которые уже индексируются и имеют трафик;
- порядок применения, чтобы карта и страницы не разошлись;
- **план отката**.

**Правки кода не требуются и не предполагаются.** Если считаешь, что нужен код —
обоснуй отдельно; по умолчанию задача решается в данных.

## Задача 3 — проверить смежное

- Правда ли, что 60 путей смешивают города **из-за `canonicalPath`**, или причина
  в данных (одна запись привязана к нескольким городам)? Это разные баги.
- Есть ли записи с `canonicalPath`, указывающим на **чужой** путь (не `/venues/*`).

## Что аннулировано — НЕ делать

- **Не сливать записи.** Эвристика схожести даёт HIGH для идентичных названий, но
  «Дом культуры» в Саратове и в Екатеринбурге — разные здания. Слияние уничтожило бы
  17 реальных площадок. Предупреждение `sameCity: false` при 18 записях из 18 городов
  бесполезно.
- **Не менять `Venue.slug`** и **не вводить `/{city}/venue/{slug}`**. Уникальный slug
  уже есть, публично не используется, а хеш-хвост в URL не резолвится (404).
- **Не расширять контент-гейт**, не трогать allowlist.
- Не чистить БД. Задача read-only + план.
