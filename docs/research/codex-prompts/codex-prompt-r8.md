## Задача 1 — тиры по ВСЕМ 4304, не только по живым

Считать все площадки, включая те, у которых нет событий.

Тир определяется готовностью контента, а не наличием событий. Предлагаю:

| Tier | Критерий | Объём |
|---|---|---|
| **TIER1** | описание ≥120 симв. + адрес + фото | писать в первую очередь |
| **TIER2** | описание есть, нет фото или неполно | добить и писать |
| **TIER3** | адрес есть, описания нет | нужен текст |
| **HOLD** | нет ни описания, ни адреса | сначала данные, потом текст |

HOLD — отдельным списком: их нельзя чинить текстом, у них нет сырья.

Отдельно: **`OUTDOOR_LOCATION` (242) и `MEETING_POINT` (342) тирировать
по своим правилам.** Для локаций важнее координаты, описание, hookFact и
wayToFind, а не описание площадки с афишей.

**Результат — `docs/research/venue-tiers-20261002/`: CSV + markdown, в git.**

## Задача 2 — разрезы по городам

Те же тиры, но срез по городам: сколько площадок каждого тира в городе.
Отдельно — доля HOLD: если она высокая, город получает контент позже, даже
если площадок много.

## Задача 3 — места для route в «Мой день»

Какие площадки пригодны как точки маршрута: есть координаты, hookFact или
wayToFind. Это вход в задачу про маршруты — посчитать и отдать список.

## Задача 4 — план первой партии контента

По TIER1: сколько страниц, в каком порядке, что писать в каждой. С оценкой
труда. **Не писать контент — только план**, объём утверждает owner.

## Что аннулировано

- **78 дублирующихся путей — не подтверждено.** В БД по `canonicalPath`
  ровно **3**. Число 78 пришло из CSV r4, который группировал пути sitemap,
  то есть считает другое множество. Проверь три настоящих дубля, но не
  планируй миграцию на 78.
- **Не сливать «Руки Вверх», «Дом культуры» и подобное.** Это разные площадки
  в разных городах; эвристика схожести даст HIGH и уничтожит реальные записи.
- **Не считать через `/api/public/venues` и `/api/admin/events`** — они
  игнорируют `offset` и фильтры по дате. Только прямые запросы к БД.
  Для сверки: `Event` в БД — 103 833, админ-API показывает 8 428.
- **Не чистить БД.** Задача read-only + планы.
