Цель: **начать писать контент по городам, не создавая thin layer.** Нужен не
просто счётчик, а понимание, хватает ли материала в каждом городе.

Прямого доступа к БД у меня нет, снимок нужен от тебя. Материалы r4 читай в

## Задача 1 — снимок БД (read-only)

Результат — в `docs/research/city-content-20261002/`, **не в scratch**: 01.10 на
этом уже почти потерялась точка отсчёта.

По каждому городу:

| Поле | Зачем |
|---|---|
| `slug`, `name`, тип (город / регион) | идентификация |
| число площадок, число локаций | объём |
| число событий за 30 дней | активность, признак живого города |

Сводка сверху: сколько всего площадок и локаций в БД, сколько проходит гейт,
сколько исключено и по каким причинам.

**Плюс дельта по синку** — то, что я не смог посчитать сам. `createdAt` и
`updatedAt` за последние 24 часа с группировкой по источнику. Закроет вопрос
«сколько добавилось и ушло за ночной синк».

## Задача 2 — тиры по готовности к контенту

Прошлые батчи (14 / 21 / 39) считались по sitemap. Пересчитай по БД и по
критерию, прямо отвечающему на вопрос «thin или нет».

Город годен к контенту, если у него есть материал на N страниц **с
заполненными данными**, а не просто N URL в карте. Пустая карточка в sitemap —
ровно тот thin layer, которого избегаем.

Предложи пороги и обоснуй. Форма вывода:

```
Tier N — городов: M
  пример: slug (площадок X, из них с текстом Y, локаций Z, событий W)
```

**Отдельно отметь города, которые в Tier попали, но писать по ним нельзя** —
мало заполненных карточек. Их надо чинить данными, а не текстом.

## Задача 3 — сверка с sitemap

Сверь снимок с `venues.xml` live и объясни расхождения:

- запись в БД, но не в карте — гейт, pageStatus или stale;
- запись в карте, но не в БД — так быть не должно, найди причину;
- **92 URL отдаются дважды** (1378 записей / 1286 уникальных). Учти при
  подсчёте по городу, иначе города с дублями выглядят богаче, чем есть.

---

## Чего не делать

- **Не начинать контент.** Сначала снимок и тиры, объём утверждает owner.
- **Не считать через `/api/public/venues`** — игнорирует `offset`, отдаёт одну
  первую страницу. Только БД.
- **Не чистить и не править БД.** Задача read-only.
- Не расширять гейт.

## Формат

Таблица в репозитории: markdown для чтения, CSV для обработки. В ответе — путь к
файлам, сводные числа по tier'ам и отдельным списком города, где писать нельзя
из-за нехватки данных.

Проверки запускать не нужно — код и БД не меняются.
