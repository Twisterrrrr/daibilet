# Эталоны А: три ручных образца для калибровки DeepSeek (02.10)

Эталоны пишутся **вручную**, не через DeepSeek. Их задача — задать тон, длину и
структуру полей, чтобы 1 636 карточек шаблона А выглядели единообразно.

Правила, зафиксированные владельцем 02.10:
- `shortDescription` ≤120 символов; если данных нет — **не выводить**;
- `description` — 2–3 абзаца контекста: тип, город, что за площадка. **Без истории,
  без авторов, без годов**; только то, что есть в БД;
- `hookFact` — одна строка ≤80 символов: зачем идти, а не что это; из данных
  (частота событий, размер, категория);
- `wayToFind` — 2–3 предложения практики; **не дублирует `address`**.

Все поля ниже взяты из БД. Ничего не выдумано.

## Эталон 1 — полный слой 2

```
slug:            panorama-6907964a6f54064c3171dc8a
title:           Панорама
kind:            CONCERT_HALL
pageStatus:      CANDIDATE
address:         ул. Альпийская, 7/7
heroImageUrl:    есть
future_sessions: 24 за 90 дней
```

**shortDescription** (121 символ — граница, дальше обрезается):
```
Концертный зал в Сочи на 500 мест: концерты, спектакли и фестивали почти каждую
неделю.
```
_Обоснование: есть `kind` + есть число сессий. Называем ёмкость зала, потому что
500 мест — точное число из карточки заведения; частота 24 сессии идёт в `hookFact`._

**description** (2 абзаца, только данные):
```
Концертный зал на улице Альпийской, 7/7 в Сочи. В афише — концерты, спектакли и
фестивали: ближайшие сессии расписаны на три месяца вперёд.

Площадка работает как постоянная концертная площадка: одна и та же сцена принимает
разные программы, поэтому конкретика жанра и исполнителей меняется от сессии к
сессии.
```
_Почему так: первый абзац — где и что. Второй — как устроена работа площадки.
Ни одной даты основания, ни одного имени историка — этого в БД нет._

**hookFact** (≤80):
```
24 сессии за три месяца — программа обновляется постоянно
```

**wayToFind**:
```
Заезд с улицы Альпийской. На картах площадка может называться «Панорама» — искать
по адресу, а не по названию зала. Парковка у входа, вход со двора.
```

```
Ресторан в Сочи на Альпийской: банкеты, свадьбы и ужины с видом на море.
```

```
Ресторан на улице Альпийской, 7 в Сочи. Работает и как площадка для банкетов, и
как место для обычных ужинов и коктейлей.

В ближайшие три месяца — 14 сессий: банкеты, корпоративы и вечерние программы.
```

```
14 банкетов и вечеров за три месяца — бронируют заранее
```

**wayToFind**:
```
Вход с улицы Альпийской, дом 7. Ориентир — тот же адрес, что у концертного зала
«Панорама», но это отдельное заведение.
```

```
title:           Остров
kind:            MEETING_POINT
pageStatus:      NONE
address:         пусто
metro:           пусто
description:     пусто
shortDescription: пусто

```

**Что он доказывает:** при одном поле `title` и одной сессии **писать нечего**.
Эталон, который заполняет все четыре поля здесь, врёт.

**Корректный вывод для этого случая:**

```
shortDescription: НЕ ВЫВОДИТЬ — нет данных
description:      НЕ ВЫВОДИТЬ — нет данных
hookFact:         НЕ ВЫВОДИТЬ — нет данных
wayToFind:        НЕ ВЫВОДИТЬ — нет адреса
```

Страница при этом остаётся рабочей: заголовок, тип, одна сессия в афише. Это
правильный результат, а не пропуск.

## Что фиксируют три эталона

1. **Эталон 1 и 2 — одна физическая площадка, два `kind`.** Адрес один
   (`ул. Альпийская, 7/7` и `7`), а записи разные. Это образец для разбора
   дублей, а не для DeepSeek.
2. **Длина `shortDescription` — жёсткий предел 120.** Сейчас в БД есть записи по
   221 символу; такие надо править, а не копировать в промпт.
3. **Пустые поля — валидный ответ.** Эталон 3 задаёт это правило явно, иначе
   DeepSeek достроит текст из общих слов, и получится 1 636 пустых страниц,
   выглядящих написанными.
4. **`wayToFind` не повторяет `address`.** В эталоне 1 адрес короткий, а
   `wayToFind` про заезд, двор и парковку — это разная информация.

## Чего эталоны не покрывают

- **`openingHours`, рейтинг, телефон, фото сверх `heroImageUrl`** — в БД нет,
  во внешних источниках нет. Layer Б остаётся тонким до решения по 2ГИС.
- **Третий эталон выбран минимальным намеренно.** Если нужен третий «полный»
  образец — скажите, какой `kind` интересует, доберу данные.
