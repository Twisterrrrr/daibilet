# AI-рерайт описаний событий (admin MVP)

**Дата:** 2026-09-15
**Статус:** UI draft + проверяемый batch для TC

## Зачем

Source-описания с Ticketscloud / других фидов часто копируются 1:1. Редакционный текст в `EventOverride.description` должен добавлять полезную структуру и проверенные факты, не ломая sync source. Формальная уникальность сама по себе не является целью.

## Flow

1. Админ открывает карточку события → блок «Контент (override)».
2. Кнопка **«Сгенерировать рерайт»** → `POST /api/admin/events/:id/rewrite-description`.
3. Backend читает source description (fallback: текущий override), город, площадку, адрес, категорию, возраст, а также `startsAt` / `endsAt` активных сеансов, и вызывает OpenAI с системным промптом «шестиугольник безопасности».
4. Ответ **только в UI** (колонки Было / Стало). В БД ничего не пишется.
5. Админ правит textarea и жмёт **«Сохранить контент»** → существующий `PATCH .../override`.

TC sync **не затирает** override (import-guard). Для программы с `metaExternalId` новые слоты наследуют редакционный текст только при точном совпадении названия и исходного описания; существующий override никогда не перезаписывается.

## Канон структуры

- один-два коротких вводных абзаца;
- два-четыре раздела `##` с предметными названиями;
- нельзя добавлять `## О событии`, потому что это уже заголовок внешнего блока страницы;
- при двух и более подтвержденных фактах обязателен раздел `## Особенности` со списком;
- неизвестные материалы, программа, включенные услуги и условия не додумываются;
- одно полотно без смысловых блоков отклоняется backend-валидатором.

## Канон длительности

- Если организатор явно указал длительность в исходном описании, сохраняем её без пересчёта.
- Если в тексте длительности нет, вычисляем её по активным сеансам: `endsAt - startsAt`.
- Расчётное значение округляем до ближайших 5 минут: 67 минут → 65, 68 минут → 70.
- Если все сеансы после округления имеют одинаковую длительность, рерайт может назвать одно значение.
- Если длительность различается, пишем «зависит от сеанса» и называем варианты; при большом числе вариантов — диапазон. Одно фиксированное значение в таком случае запрещено.
- При отсутствующем, некорректном или более раннем `endsAt` длительность не выводим и не придумываем.
- В готовом тексте не упоминаем Ticketscloud и технические поля расписания.

## Env

```bash
OPENAI_API_KEY=sk-...
# optional:
OPENAI_REWRITE_MODEL=gpt-4.1-mini
```

Ключ — на **backend** (куда ходит admin API). Без ключа кнопка показывает понятную ошибку, сайт не падает.

## Batch

Пакет `apps/backend/scripts/tc-editorial-apply.mjs` принимает только версии со статусом `APPROVED`, корректным source hash и канонической структурой. До записи выполняется dry-run; перед транзакцией сохраняется backup, а публикация фиксируется в `EventChangeLog`. Одна рабочая итерация: 100 программ, пять QA-пакетов по 20.

## Границы MVP

- Нет auto-publish на sync и нет Anthropic dual-provider.
- Нет draft-статуса в БД и нет автосохранения рерайта.
- SEO override (`seoTitle` / `seoDescription`) уже в схеме — рерайт их не трогает.
- Rate limit: ~1 запрос / event / 5 с (in-process).
