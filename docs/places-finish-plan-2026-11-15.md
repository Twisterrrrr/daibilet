Цель: дать редакции безопасный и понятный процесс создания, наполнения, проверки и публикации PDP мест. Работу вести на ветке `codex/places-editorial-completion`; production не менять до отдельного решения о релизе.

## 10 шагов

1. Проверить чистоту ветки и результат сборки изолированного preview; сохранить план и фактические результаты. **Готово:** ветка `codex/places-editorial-completion`, сборка `11967928a`.
2. Проверить полный PDP без продаж (Врубелевский корпус): hero, факты, адрес, пустая афиша, редакционный контент и robots. **Проверено:** preview HTTP 200, breadcrumbs внутри hero, 0 событий/сеансов; опубликованный информационный PDP индексируется.
3. Проверить полный PDP с активной программой (Музей Гарри Поттера): афиша, цены, кнопки покупки, отсутствие копирования слотов в редакционный документ. **Проверено:** preview HTTP 200, 86 событий/сеансов, афиша и цены присутствуют; DRAFT виден только в admin preview, публичный DTO возвращает `pdp=null`, страница noindex.
4. Проверить создание/сохранение/повторное редактирование PDP из Admin UI, включая DRAFT и восстановление сохранённого контента. **Частично:** DRAFT создан через admin API и загружается в редакторский preview; визуальное взаимодействие в браузере Codex блокирует HTTP Basic.
5. Проверить кандидата места: импортированная карточка доступна пользователю, остаётся noindex и не попадает в sitemap до редакционной публикации. **Публичный API проверен:** кандидат с черновиком отдаёт `isIndexable=false`; sitemap нужно проверить отдельно.
6. Проверить редакционный статус публикации отдельно от коммерческого состояния: PUBLISHED без продаж индексируется; продажи не переводят DRAFT в публикацию. **Проверено на двух объектах:** Врубель индексируется при нуле сеансов; Гарри Поттер остаётся noindex при 86 сеансах, DRAFT публично не отдаётся.
7. Исправить выявленные UX-дефекты шаблона PDP: крошки внутри hero, выравнивание отступов, отсутствие дубля адреса/площадки, одна строка пиктограмм и ясная CTA, бейджи без повторов, структурированный контент. **Код исправлен:** крошки внутри hero обоих шаблонов; нижний дубль адреса удалён у заведений; действия с маршрутом и поделиться собраны в иконки рядом с CTA.
8. Проверить медиа, источники, факты и чек-лист готовности; подготовить копирайтеру образец на реальном объекте без неподтверждённых деталей. **Текстовый образец создан с источниками; редактору осталось проверить текст и добавить галерею.**
9. Прогнать целевые typecheck, тесты и production build; проверить маршруты, canonical/robots, sitemap и API-контракты. **Эта итерация прошла:** web typecheck; `web:test:ci` 356/356; production build; изолированный preview/API smoke. Sitemap и canonical нужно проверить отдельно.
10. Развернуть на обычный staging безопасным способом, пройти smoke-тесты обоих сценариев и оформить отчёт. **Изолированный preview запущен на localhost:3012; общий staging checkout не переключался из-за незатреканных изменений медиа.** После принятия Places перейти к ЛК поставщика и финконтуру.

- Не публиковать редакционные черновики автоматически.
