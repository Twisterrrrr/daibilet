## 5. Предложение по типам площадок

Ввести поле `Venue.kind`:

- `venue` - обычная событийная площадка;
- `museum_art_space` - музей, галерея, арт-пространство;
- `theater` - театр;
- `concert_hall` - концертный зал, ДК, филармония;
- `club_bar_restaurant` - клуб, бар, ресторан;
- `pier` - причал;
- `meeting_point` - точка встречи экскурсии;
- `outdoor_location` - парк, площадь, улица, открытая локация;
- `sport_activity_space` - спорт/активности;
- `attraction` - достопримечательность/развлекательный объект;
- `online` - онлайн;
- `other` - не классифицировано.

Отдельно ввести `Venue.page_status`:

- `none` - публичной страницы нет;
- `candidate` - можно завести страницу после проверки;
- `published` - страница площадки опубликована;
- `hidden` - скрыта вручную.

## 6. Когда заводить карточку площадки

Автоматически не публиковать карточку площадки только из-за наличия `venue_id`.

Предлагаемые правила:

### Публиковать или предлагать к публикации

- `museum_art_space`, `theater`, `concert_hall`, `club_bar_restaurant`, `sport_activity_space`, `attraction`;
- есть 3+ будущих события;
- есть понятное название, адрес и город;
- желательно есть описание или можно написать вручную;
- площадка не выглядит как точка встречи.

### Публиковать причалы осторожно

Причалы нужны для водных событий, но их надо нормализовать:

- объединять дубли по координатам/адресу;
- хранить как `pier`;
- заводить страницу, если у причала 10+ событий или он часто встречается в водных маршрутах;
- для мелких причалов показывать только в карточке события.

### Не публиковать как площадку

- памятники и ориентиры встречи;
- адреса без бренда;
- `у метро`, `на углу`, `набережная у...`;
- временные точки сбора;
- локации, где событие фактически является маршрутом.

Их тип: `meeting_point`.

## 7. Как хранить маршруты и экскурсии

Для экскурсий нужна не только `Venue`, но и понятие точки старта:

- `Event.start_place_id` или `Event.meeting_point_id`;
- `Event.route_description`;
- `Event.venue_id` использовать только если есть реальная площадка.

Пример:

- `памятник Достоевскому` не должен становиться страницей площадки;
- это `meeting_point` для множества пешеходных экскурсий.
