# Извлечение данных событий для лендингов

## 1. Зачем нужен extraction layer

Лендинги нельзя собирать только по внешней категории или простому поиску по названию.

Причины:

- внешние категории грубые и отличаются между источниками;
- часть признаков находится в тегах;
- часть признаков спрятана в названии или описании;
- площадка может быть реальной площадкой, причалом или точкой встречи;
- одно событие может подходить сразу под несколько лендингов;
- сезонные страницы требуют дат и ключевых периодов, а не только тегов.

Поэтому между raw import и каталогом нужен слой извлечения признаков:

```text
Raw source event
  -> NormalizedEvent
  -> ExtractedEventFacts
  -> Landing eligibility
```

## 2. ExtractedEventFacts

Для каждого события сохраняем набор вычисленных признаков.

Поля:

- `event_id`;
- `source`;
- `source_event_id`;
- `category_id`;
- `primary_subcategory_id`;
- `additional_subcategory_ids`;
- `tag_ids`;
- `format_tags`;
- `topic_tags`;
- `audience_tags`;
- `seasonal_tags`;
- `feature_tags`;
- `negative_tags`;
- `city_id`;
- `region_id`;
- `venue_id`;
- `venue_kind`;
- `meeting_point_id`;
- `starts_at`;
- `date_bucket`;
- `time_bucket`;
- `price_from`;
- `has_available_tickets`;
- `confidence`;
- `matched_rules`;
- `needs_review`;

## 3. Типы тегов

### Формат

Что это за событие:

- водная прогулка;
- речная прогулка;
- теплоход;
- катер;
- пешеходная экскурсия;
- автобусная экскурсия;
- обзорная экскурсия;
- концерт;
- спектакль;
- шоу;
- мастер-класс;
- выставка;
- фестиваль;
- автоспорт.

### Тема

О чем событие:

- разводные мосты;
- дворы и парадные;
- коммуналки;
- реки и каналы;
- Новый год;
- 9 мая;
- салют;
- ужин;
- музыка;
- стендап;
- детский праздник.

### Аудитория

- детям;
- семьям;
- взрослым;
- парам;
- компаниям.

### Особенности

- с ужином;
- с музыкой;
- ночное;
- вечернее;
- открытая дата;
- на открытом воздухе;
- в помещении;
- рядом с метро.

### Negative tags

Признаки, которые исключают событие из некоторых лендингов:

- не водное;
- не автобусное;
- не семейное;
- не салют;
- нерелевантное совпадение.

Например, слово `речн` может попасться в названии музыкальной группы или другом контексте. Такое событие не должно попадать в `Речные прогулки`, если нет подтверждающих водных тегов.

## 4. Источники признаков

Признаки извлекаются из:

- внешней категории;
- внешних тегов;
- названия;
- описания;
- названия площадки;
- типа площадки;
- адреса;
- даты и времени;
- ticket sets;
- meta-event;
- ручных правок модератора.

Приоритет источников:

1. Ручная правка.
2. Явные внешние теги.
3. Внешняя категория.
4. Площадка/тип площадки.
5. Название.
6. Описание.
7. Эвристики по дате/времени.

## 5. Confidence

Каждому правилу задаем уверенность.

Пример:

- внешний тег `Водные экскурсии` -> `водная прогулка`, confidence `0.95`;
- venue kind `pier` + категория `Экскурсии` -> `водная прогулка`, confidence `0.85`;
- название содержит `теплоход` -> `теплоход`, confidence `0.75`;
- описание содержит `ужин` -> `с ужином`, confidence `0.65`;
- только слово `май` -> недостаточно, confidence `0.1`.

Правило публикации:

- `confidence >= 0.8` - можно использовать автоматически;
- `0.5 <= confidence < 0.8` - использовать как кандидат, показать в модерации;
- `< 0.5` - не использовать для лендинга без подтверждения.

## 6. Правила для ключевых лендингов

### Речные прогулки

Включать, если есть хотя бы один сильный признак:

- тег `Водные экскурсии`;
- тег `Реки и каналы`;
- тег `На теплоходе`;
- тег `Водная экскурсия`;
- тег `На катере`;
- тег `Теплоходные экскурсии`;
- `venue_kind = pier`;

Дополнительные признаки:

- название содержит `теплоход`, `катер`, `реки`, `каналы`, `прогулка по воде`;
- описание содержит водные маршруты.

Исключать:

- если совпадение только по части слова без водных тегов;
- если категория не `Экскурсии` и нет признака причала/водного формата.

### Ужин на теплоходе в Москве

Включать, если одновременно:

- город или регион: Москва / Московская область;
- формат: водная прогулка, теплоход или катер;
- есть признак питания: `ужин`, `банкет`, `фуршет`, `ресторан`, `с ужином`.

Дополнительные признаки:

- вечернее время;
- музыка или шоу-программа.

Не включать:

- обычные водные прогулки без признака питания;
- ресторан без водного признака;
- теплоходные прогулки в Санкт-Петербурге.

### Салют 9 мая

Включать, если:

- дата около 9 мая;
- есть ключевые слова `салют`, `день победы`, `9 мая`, `праздничная программа`, `парад`;
- или событие вручную добавлено модератором.

Не включать:

- события, где `9 мая` найдено только как фрагмент даты в тексте;
- события без праздничного контекста.

Для текущего TC inventory страница должна быть demand-capture с пустым состоянием или похожими майскими событиями.

### Отмечаем Новый год

Включать, если:

- дата в период декабрь - первая половина января;
- название/описание/теги содержат `новогод`, `новый год`, `елка`, `ёлка`, `рождество`, `праздничн`;
- категория: шоу, детям, концерты, театры, фестивали.

Дополнительные признаки:

- аудитория `детям`;
- формат `шоу`, `спектакль`, `концерт`, `вечеринка`.

### Автобусные обзорные экскурсии

Включать, если:

- есть `автобус`, `автобусная`, `автобусный тур`;
- и есть `обзорная`, `экскурсия`, `city tour`, `тур`;
- категория: экскурсии.

Исключать:

- водные события с тегами `водная`, `теплоход`, `катер`, `реки и каналы`;
- фестивальные автобусные трансферы, если они не являются обзорной экскурсией.

### Дворы, парадные и коммуналки

Включать, если:

- теги `Дворы и парадные`, `Экскурсия по парадным`, `Экскурсия по коммуналкам`, `Экскурсия по дворам`, `Интерьерная`;
- город: Санкт-Петербург;
- категория: экскурсии.

### Разводные мосты и ночные прогулки

Включать, если:

- тег `Разводные мосты`;
- или водный формат + тег/слово `ночные`;
- город: Санкт-Петербург.

## 7. Правила дат и времени

### Date bucket

- `today`;
- `tomorrow`;
- `this_weekend`;
- `next_7_days`;
- `next_14_days`;
- `custom_period`;
- `seasonal_period`.

### Time bucket

По локальному времени города:

- `morning`: 06:00-11:59;
- `day`: 12:00-16:59;
- `evening`: 17:00-22:59;
- `night`: 23:00-05:59.

Важно: в базе хранить UTC, но bucket считать для города/локации.

## 8. Табличная eligibility-модель

Каждый лендинг должен уметь объяснить, почему событие попало в выборку.

Пример:

```json
{
  "landing": "rechnye-progulki",
  "event_id": "...",
  "eligible": true,
  "confidence": 0.95,
  "matched_rules": [
    "tag:Водные экскурсии",
    "venue_kind:pier"
  ]
}
```

Это нужно для:

- отладки;
- модерации;
- исключений;
- доверия к автоматике.

## 9. Ручные overrides

Нужны ручные правила:

- force include event into landing;
- force exclude event from landing;
- override category;
- override subcategory;
- override tags;
- mark venue as meeting point/pier/real venue;
- merge duplicate venues;
- mark bad price.

## 10. Минимальный порядок реализации

1. Схлопнуть TC events в `Event` + `EventSession`.
2. Добавить `ExtractedEventFacts`.
3. Добавить словарь extraction rules.
4. Добавить расчет `date_bucket` и `time_bucket`.
5. Добавить `LandingRule`.
6. Добавить `LandingEventMatch` с `confidence` и `matched_rules`.
7. Сделать админский экран проверки попадания событий в лендинги.
