# SEO-аудит daibilet.ru - вердикт 2026-09-02

**Цель:** что мешает росту органики и что чинить в первую очередь.  
**Срез:** live MSK + код `feat/next-monorepo` + Вебмастер (mobile warning).

---

## Вердикт (коротко)

Сайт **технически уже не «сломан» для индексации** (sitemap, IndexNow, canonical хабов, soft-404→HTTP 404, dense meta на ядре). Рост тормозит не отсутствие title/desc, а:

1. **Мало страниц с устойчивым спросом в индексе** (тонкие лендинги / city×intent ещё в пилоте).
2. **Сигнал «не mobile» в Вебмастере** (часто ложный/устаревший; viewport уже есть) - снижает доверие к качеству.
3. **Контентная плотность vs афишный каталог** - много URL с переменным числом офферов → то noindex, то index.
4. **Слабая перелинковка и ЧПУ подборок** (`/podborki?city=` вместо `/podborki/c/{city}`).
5. **CAPS/шумные title от поставщика** портили сниппеты (частично закрыто `formatPublicTitle`).

Без расширения **индексируемого** city×intent и без стабильного mobile/Core Web Vitals на главной/афише трафик останется около нуля даже при ежедневном sync событий.

## Про «98 городов»

Счётчик = **публичные destinations `type=city` после geo-политик** (standalone / allowlist), а не «все населённые пункты из TC sync».

- Мелкие города уходят в `cityToRegion` (пример: **Донецк (Ростовская область)** → Ростовская область) - это **не** Донецкая область.
- `foreignCities` режутся намеренно.
- Поэтому при росте событий **число городов на главной почти не растёт** - растут офферы внутри уже открытых хабов.
