# EventPage: пакетное добавление Event ID

Для больших групп слотов используется отдельная операция, которая добавляет связи к одной EventPage и не заменяет уже существующий список.

```http
POST /api/admin/event-pages/{eventPageId}/events/batch
Content-Type: application/json
Authorization: Basic …
```

```json
{
  "eventIds": ["evt_…", "evt_…"],
  "changeNote": "Пакетная привязка подтверждённых слотов одной серии"
}
```

- Один запрос принимает от 1 до 5 000 уникальных Event ID. Внутри API записи выполняются частями по 500, но вся операция обёрнута в одну транзакцию: ошибка откатывает весь запрос.
- Повтор того же запроса безопасен: уже связанные с этой страницей ID возвращаются в `alreadyLinkedEventIds`, новые — в `addedEventIds`.
- Если хотя бы один ID связан с другой EventPage, весь запрос отклоняется с HTTP 409 без частичной записи. Сначала нужно отдельно решить перенос.
- Пакетное добавление доступно только до публикации страницы (`publishedAt` отсутствует и `isIndexable=false`).
- Ответ содержит `addedCount`, `alreadyLinkedCount`, общее `eventCount` и списки обработанных ID.
- Операция не объединяет события по поставщику, площадке, названию или Ticketscloud parent. Связываются только ID из переданного списка.
- Обычный `PUT /api/admin/event-pages/{id}/events` остаётся полной заменой связей с пределом 50 ID. Использовать его для последовательных порций нельзя.

Для 2 000 подтверждённых ID достаточно одного POST с полным списком. Если группа больше 5 000, можно передать несколько непересекающихся пакетов: каждый запрос атомарен и добавляет связи.
