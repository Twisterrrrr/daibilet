# Карта соответствий Event → PDP / слот / архивный URL

**Снимок:** 27.10.2026. **Среда:** production, только чтение через уже поднятый локальный туннель; изменений БД, canonical, sitemap и redirect-правил не выполнялось.

## Принятое правило

- Индексируемая сущность — PDP события. Сеансы и билетные слоты живут внутри этой страницы и не получают самостоятельные индексируемые PDP.
- Пока соответствие старого URL устойчивому PDP не доказано и целевой PDP не готов, старый URL сохраняет fallback. Не ставить `noindex`, не менять canonical и не редиректить массово.
- Прошедшее событие не должно исчезать с 404 только потому, что у него больше нет продаваемого сеанса. Если надёжной группировки нет, сохраняется самостоятельный архивный PDP.
- `MetaEvent` — сильная подсказка для поиска серии, но не автоматическое разрешение на слияние: встречаются крупные группы, отличающиеся редакционные выпуски и варианты места проведения.

## Объём и ограничения аудита

- Живой `/sitemaps/events.xml` содержал 4 346 URL; 4 008 URL оканчивались 24-значным hex-ID. Это формат идентификатора, сам по себе он не доказывает, что каждая запись является отдельным слотом.
- Для Ticketscloud в БД найдено 1 375 значений `metaExternalId`; 1 121 связывает более одной Event-записи, 127 групп охватывают больше одного города. Медианный размер группы — 8 Event-записей; 21 группа превышает 1 000, максимальная — 4 500. Поэтому полное автоматическое объединение по `metaExternalId` небезопасно.
- Сопоставление ID из sitemap с `EventSourceLink` выявило 553 TC meta-группы в текущей карте. В 7 группах sitemap содержал по два URL (14 страниц). Все 14 проверены: HTTP 200, каждая имела self-canonical.

## Следующий проход карты

1. Экспортировать полную выборку URL из Google Search Console/Вебмастера с 404/«Страница не найдена» и сопоставить с текущими Event/EventSourceLink. Три примера выше не покрывают исторический хвост.
2. Для текущих sitemap URL построить реестр `public URL → Event ID → provider external ID → meta group → proposed PDP → decision → confidence`.
3. Добавить ручную проверку площадки/организатора и текста для туров и спецвыпусков. Большие TC meta-группы (`>30` записей) не объединять автоматически; сначала разбить на продукты/города/серии.
4. После подтверждения создать стабильные PDP и только потом менять canonical/redirect/sitemap. До этого fallback сохраняется.

## Проверяемые инварианты перед SEO-изменениями

- У каждой прежней индексируемой ссылки остаётся HTTP 200 или однозначный 301 на готовый PDP; 404 не является допустимым способом «склеить слоты».
- У каждого PDP есть один self-canonical; слот или старый slug получает canonical/redirect только при однозначной связи с PDP.
- Sitemap содержит PDP, а не дублирующие slot-страницы; страницы со спорной идентичностью пока не удаляются из карты.
- Проверить 200/301/404, canonical, robots, sitemap membership и JSON-LD до и после переключения; сохранить список старых URL для rollback.
