# Задание Cline: связь админки с ЛК покупателя

База: свежий `origin/codex/supplier-pii-and-ui-plan-2026-10-19` после интеграции с владельцем; создайте отдельную `cline/buyer-admin-bridge-ui`. Перед началом назовите base SHA и затрагиваемые файлы. Не меняйте `apps/backend`, `packages/db`, `packages/contracts`, env, миграции и финконтур. Не деплойте.

1. В `apps/web/src/components/AccountPurchasesPage.client.tsx` замените устаревшее обещание «только Ticketscloud и Teplohod» на описание единого списка внешних и внутренних заказов. Не обещайте появление гостевых покупок по email, пока email не подтверждён сервером. Покажите ясное пустое состояние для неподтверждённого адреса после появления признака в DTO; до контракта не угадывайте статус в браузере.
2. Подготовьте интерфейс `/admin/buyers` как реестр покупателей, а не сотрудников. Сохраните быстрый переход к заказам. Отдельно показывайте «аккаунт» и «гостевой покупатель», внутренние и внешние заказы, последний контакт/обращение. Новые поля подключайте только по готовому unified admin buyer DTO Codex; не вычисляйте числа из ограниченной страницы заказов. До выпуска DTO честно обозначьте ограничение текущего списка внешними заказами.
3. В карточке заказа и покупателя нарисуйте связи «заказы / возвраты / обращения», но не добавляйте имитацию завершённых денежных действий. Полные контакты видны только при серверном `orders.pii.read`, без клиентского маскирования как меры защиты.
4. Сверьте UX с `docs/buyer-admin-bridge-2026-10-20.md` и legacy SPBBOATS `packages/backend/src/admin/admin-site-users.controller.ts`, `packages/backend/src/account/purchase-read.service.ts`. Не копируйте legacy API один к одному.
5. Дайте скриншоты desktop/mobile и проверки: typecheck, затронутые тесты, smoke для пустого/ошибочного/без права. В отчёте перечислите реальные DTO gaps и отдельно проверьте отсутствие раскрытия PII в HTML/JSON для роли без права.

Принцип: новое поле в UI не означает готовую серверную защиту. Роль нельзя менять демо-переключателем в production. Для трёх источников поставщика (`IMPORT`, `PORTAL`, `API`) и трёх способов продажи сохраняйте независимые метки; не выводите канал оплаты из типа поставщика.
