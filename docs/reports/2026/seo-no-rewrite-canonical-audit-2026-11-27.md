# SEO-пилот EventPage без рерайта: live-аудит canonical, 27.11.2026

## Вывод

Production не менялся. По текущей повторно сформированной выборке **0 подтверждённых новых канонических страниц**, которые можно открыть без переноса уже существующего индексируемого URL. Среди 3 190 кандидатов 3 189 ведут на уже существующий старый URL с `index, follow`; ещё одна EventPage требует разбора группировки. Это означает, что открытие новых стабильных URL сейчас является миграцией URL, а не чистым расширением индексации.

У всех 3 190 стабильных URL EventPage получен HTTP 200, effective robots `noindex, follow`, и HTML canonical совпал с canonical публичного API. Ни один стабильный URL не найден в проверенном sitemap событий. Старый URL присутствует в sitemap у 2 639 записей; у 551 старый canonical отсутствует в sitemap. Отсутствие в sitemap само по себе не означает `noindex`: эти адреса остаются отдельными старыми URL, и их фактические robots/HTTP не были индивидуально обойдены в полном объёме.

Индексируемость — разрешение обхода, а не подтверждение попадания в поисковую выдачу. Данные Search Console и Яндекс Вебмастера не запрашивались; `searchEngineIndexPresence` в выгрузке везде `NOT_CHECKED`.

## Объём и критерии выборки

Заявленные ранее 3 171 кандидата и 2 946 строгих кандидатов не удалось независимо воспроизвести: сохранённого списка ID и исходного SQL этих множеств нет. Для этого аудита заново применена документированная диагностическая выборка к текущей production БД, только чтение: EventPage без активной редакционной версии, связанное событие READY, непустые title/city/venue и описание длиннее 20 символов, покупательский путь и цена от 100 рублей либо бесплатное событие, а также хотя бы один будущий открытый слот/продажа. Получилось 3 190 EventPage с хотя бы одним подходящим связанным Event, 2 966 — если требуют подходить все связанные Event, разница 224. Эти значения заменяют прежнюю цифру только для данного среза и именно данного SQL, а не доказывают ошибку исторических чисел.

В выборке 3 190 EventPage и 17 246 связей EventPage-Event; 3 186 страниц сопоставлены через публичный каталог/API, остальные через прямые публичные API-маршруты. Четыре неизвестных в первоначальной выгрузке Teplohod дополнительно проверены API напрямую: HTTP 200, `AVAILABLE`, DRAFT-маршрут, доступность покупки подтверждена. Поэтому они классифицированы вместе с остальными существующими canonical URL.

Для каждого нового stable URL получен HTML head с User-Agent Googlebot. По 20 строкам дополнительно сверены ID, slug страницы, canonical HTML, API-событие и sitemap; расхождений HTML/API canonical не обнаружено. Sitemap `/sitemaps/events.xml` содержал 4 635 адресов на момент выгрузки.

## Неоднозначная группировка

EventPage `56ae0586-a831-4f74-8f3b-e5d24ab52393`, slug `ochen-strannye-administrativnye-dela-krasnoyarsk`, связана с восемью Event и шестью qualifying Event. Публичный каталог сопоставляет один slug EventPage с двумя разными groupKey (merge и tc-meta). HTML canonical ведёт на старый self-canonical URL `https://daibilet.ru/events/ochen-strannye-administrativnye-dela-6ae19daa6d18fa67a4c3d553`, который есть в sitemap. Это не доказанный дубликат URL, но конфликт идентичности/группировки; автоматическое переключение исключено.

## Миграция URL — отдельный контур

Для 3 189 строк подготовлена карта `старый canonical → stable EventPage URL`. Это инвентаризация возможной миграции, не инструкция автоматически включить redirect или закрыть старый URL. В частности, 551 старых canonical отсутствуют в sitemap, что требует проверить отдельно до решения о переходе.

До любой миграции для выбранных URL нужно проверить HTTP/robots/canonical обеих сторон, ответ старого URL и redirect chain, внутренние ссылки, sitemap после переключения и правила сохранения старого адреса. По действующему архитектурному решению URL старого Event сохраняется как fallback, пока опубликованная EventPage не подтверждена; нельзя выводить URL-владение только из заголовка или эвристики.
