# SEO-аудит индексируемой поверхности DAIBILET

**Срез production:** 28.11.2026. База только читалась, API/HTML/sitemap запрашивались. В ходе аудита SEO-флаги и приложение не менялись.

## Вывод

В свежем `/sitemaps/events.xml` найдено **4 168 уникальных URL**. С учётом 551 старого canonical из предыдущего аудита и 15 адресов, недавно снятых из sitemap, проверено **4 709 уникальных адресов** в event-контуре.

В этой выборке **4 692 уникальных canonical URL** технически допускают индексацию и являются конечными canonical-адресами. Из них 4 164 находятся в текущей sitemap событий, 528 self-canonical доступны, но в текущей sitemap отсутствуют. В sitemap осталось 4 адреса с `noindex`. Ещё 12 `noindex` адресов находятся вне sitemap. Найден один URL, который разрешает обход, но canonical указывает на другой адрес. HTTP-ошибок и редиректов среди проверенных адресов нет.

Это техническое разрешение обхода, а не доказательство попадания страниц в Google или Яндекс. Фактическая поисковая индексация, показы и клики имеют статус **`NOT_CHECKED`**.

## Группы проверенной поверхности

| Группа | Условие | URL |
|---|---|---:|
| A | HTTP 2xx, разрешён обход, self-canonical, в текущем sitemap | 4 164 |
| B | HTTP 2xx, разрешён обход, self-canonical, вне текущего sitemap | 528 |
| C | `noindex`, в текущем sitemap | 4 |
| D | Canonical ведёт на другой URL | 1 |
| E | HTTP-ошибка или редирект | 0 |
| G | Недостаточно данных для классификации | 0 |
| H | Дополнительная группа: `noindex`, вне sitemap | 12 |

В A и B суммарно 4 692 уникальных self-canonical URL. Группа H добавлена, чтобы отдельно показать `noindex` страницы вне sitemap; её нельзя ошибочно считать UNKNOWN.

Отдельный флаг конфликтов группировки пересекается с A/B: у **4 групп** старый и новый Event ID одновременно встречаются в `groupEventIds` одной публичной Event-группы. Это 8 URL. У каждого из 4 старых URL и соответствующего нового URL при проверке были HTTP 200, `index,follow` и self-canonical. Это доказанный конфликт идентичности URL-группы для ручного разбора, но не автоматическая инструкция ставить редирект.

| Indexable, self-canonical, сейчас присутствует в sitemap | 24 |
| `noindex` | 11 |
| Canonical указывает на другой URL | 1 |

Срез production БД от 28.11 10:42 UTC связывает 545 EventPage с продаваемым событием по критерию «активный offer + будущая активная session»; 6 страниц не имеют такого связанного предложения. Статус предложения - отдельная ось, он не заменяет HTML robots/canonical. URL без актуального предложения выделены отдельно в CSV и backlog.

### Расхождение 3 189 и 3 190

Предыдущая матрица содержала 3 190 уникальных canonical URL: 2 639 были в sitemap, 551 отсутствовали. One-to-one карта возможной миграции содержит 3 189 строк, потому что из неё исключена одна EventPage с конфликтом группировки: `56ae0586-a831-4f74-8f3b-e5d24ab52393`, slug `ochen-strannye-administrativnye-dela-krasnoyarsk`. Её canonical `https://daibilet.ru/events/ochen-strannye-administrativnye-dela-6ae19daa6d18fa67a4c3d553` присутствовал в sitemap, но один slug EventPage сопоставился с двумя public `groupKey`. Это объясняет разницу между матрицей и однозначной картой, не потерянный URL.

## Sitemap и URL churn

Свежая sitemap событий получена 28.11 в 11:24:55 UTC с HTTP 200 и `x-cache-status: MISS`: 4 168 URL, без повторяющихся `loc`. Предыдущий snapshot 10:34 UTC содержал 4 169 URL. Между двумя snapshot: 14 адресов добавились и 15 исчезли.

Все 14 новых адресов при отдельной проверке отвечали HTTP 200, `index,follow` и имели self-canonical; публичный API для них вернул `AVAILABLE` и `purchaseReady=true`. У четырёх новых Event-групп API подтвердил, что старый Event ID входит в `groupEventIds` новой группы. При этом старые URL продолжают отвечать 200 с собственным canonical. Старые и новые адреса перечислены в URL-матрице. Для десяти остальных изменений соответствие одной Event-группе по `groupEventIds` не подтверждено; не выводить его только из похожего названия.

Четыре адреса с `noindex` в sitemap отвечали 200 и имели self-canonical. API-срез 10:25 UTC показывал для них `purchaseReady=true`; перед любым изменением повторно проверить доступность после синхронизации и ожидаемый редакционный статус. Автоматически не открывать их для индексации и не удалять из sitemap.

У sitemap URL есть `lastmod`; синтаксически некорректных или будущих дат не найдено. Соответствие `lastmod` реальному содержательному изменению проверить нельзя: доступный API не даёт надёжное поле последнего содержательного изменения.

## Внутренние ссылки

В полном обходе предыдущего snapshot sitemap событий (4 169 страниц) **2 433 URL не получили входящих ссылок из проверенных страниц event sitemap и 551 старого canonical URL**. Это кандидаты на orphan-проверку, но не доказанные orphan pages: главная, city hubs, тематические лендинги и venue-страницы не были включены в последнюю ссылочную выборку.

При попытке свежей загрузки всех sitemap отдельный чанк `venues.xml` ответил HTTP 503. Поэтому сайт-wide подсчёт входящих ссылок и полный перечень всех sitemap-разделов этим отчётом не подтверждаются. Перед массовым добавлением ссылок нужен отдельный граф из главной, `/events`, городских хабов, тематических лендингов и карточек площадок. Массовые ссылки автоматически не создавались.

## Качество HTML и редакционный охват

Для **4 155 URL** текущего event sitemap выполнен полный HTML-разбор; 13 добавленных позднее URL имеют проверку HTTP/robots/canonical без полного quality-парсинга. На проверенных HTML-страницах присутствовали title, meta description, H1, JSON-LD и изображения. Среди точных значений метаданных найдено 832 строки в 193 повторяющихся title-группах и 859 строк в 196 повторяющихся meta description-группах. Совпадение метаданных не доказывает дубли содержания: Ticketscloud может формировать несколько slot Event внутри одной публичной группы. Длина текста не использовалась как самостоятельная оценка качества.

Read-only срез БД 28.11 11:31 UTC содержит 7 992 EventPage:

| Редакционная группа | EventPage |
|---|---:|
| Активный рерайт + редакционный Index | 1 433 |
| Активный рерайт + редакционный Noindex | 579 |
| Без активного рерайта + редакционный Index | 0 |
| Без активного рерайта + редакционный Noindex | 5 980 |

Это редакционный статус EventPage, не фактический robots публичного URL. Активный рерайт есть у 2 012 страниц, редакционное покрытие - 25,2% каталога.

В live-проверке активных рерайтов 579 noindex EventPage не имели продаваемого связанного события по критерию active offer + будущая активная session. При этом 8 indexable EventPage не имели такого предложения; все 8 сейчас присутствуют в sitemap и отдают 200, `index,follow`, self-canonical. Они внесены в backlog для ручной проверки после подтверждённой синхронизации. SEO-флаги не менялись.

## Метод и границы

- Полный HTML обход: snapshot 4 169 URL sitemap событий + 551 canonical URL, всего 4 696 уникальных адресов; завершён 28.11 в 11:23:48 UTC. Отдельно перепроверены 14 новых URL.
- Финальная sitemap: 4 168 URL, HTTP 200, cache MISS, получена 28.11 в 11:24:55 UTC. Текущий inventory включает 551 исходный URL и недавние снятые адреса; всего 4 709 уникальных URL.
- 20 строк проверены независимым способом нормализации URL. Все 4 168 loc текущей sitemap и все 551 исходных canonical сопоставились с HTML; расхождений нормализованного ключа не найдено.
- Публичные статусы и canonical взяты из production HTML; поля БД использованы только для связей, редакционных статусов и признака продаваемого предложения. API, sitemap и DB были запрошены в течение утра UTC, поэтому синхронизация может менять membership между срезами.
- Полный обход всех sitemap-разделов и источников входящих ссылок не завершён: `venues.xml` вернул 503. Числа 4 692 canonical и 4 709 URL относятся к event-focused выборке, а не ко всему сайту.
