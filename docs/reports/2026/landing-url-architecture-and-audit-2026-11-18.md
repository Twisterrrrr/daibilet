# Канон тематических посадок и аудит URL — 18.11.2026

## Зафиксированный архитектурный принцип

Тема является основной посадочной, город — её географическим уточнением:

- `/novyj-god` — общероссийская новогодняя подборка;
- `/novyj-god/moscow` — новогодняя подборка Москвы;
- `/koncerty/moscow` — концерты Москвы, если такой городский маршрут включён для темы;
- `/teatry/kazan` — театры Казани, если маршрут поддержан каталогом и данными.

Текущие публичные адреса и их поисковую историю сохраняем. Не создаём параллельный адрес и не настраиваем редирект только ради нового интерфейса. Городские URL публикуются лишь для тем, которые разрешены маршрутной матрицей и имеют соответствующую выдачу. `/podborki/c/{city}` остаётся городским индексом подборок, а не заменой тематических URL.

Новый интерфейс каталога может менять представление и фильтры, сохраняя маршрут и его SEO-сигналы.

## Требования к внутренней перелинковке

Каждая поддерживаемая пара «тема × город» должна получать обычные HTML-ссылки:

1. С национальной страницы темы на её городские варианты.
2. С городского индекса `/podborki/c/{city}` на тематические страницы этого города.
3. С городского хаба прямо на актуальные тематические страницы этого города. Переход через общий `/podborki/c/{city}` не заменяет прямую ссылку. Сезонные и редакционно приоритетные темы нужно показывать в хабе, когда маршрут поддержан и у темы есть подходящее наполнение.
4. Из тематически подходящих статей на соответствующую тему и город.

Смена города на тематической странице должна вести на URL той же темы для выбранного города. Ссылка должна оставаться пригодной для робота без выполнения клиентского JavaScript.

Если городская страница не поддерживается для темы, интерфейс не должен придумывать URL. Он должен оставить выбор на общем маршруте либо предложить только доступные города.

## Результат проверки на 18.11.2026

### Доступные live-сигналы

- После смены сети host-route к production остался привязан к прежнему шлюзу. После его обновления HTTPS заработал. Это была локальная сетевая проблема.
- `https://daibilet.ru/robots.txt` и `https://daibilet.ru/sitemap.xml` ответили HTTP 200. `robots.txt` указывает sitemap index `https://daibilet.ru/sitemap.xml`, который ссылается на `/sitemaps/landings.xml`.
- Live `/sitemaps/landings.xml` ответил HTTP 200 и содержит 104 URL. Первый запрос в медленной сети занял 39,5 секунды, повторный — 7,9 секунды с `X-Cache-Status: HIT`. Эти клиентские замеры не доказывают медленную генерацию на сервере. `/sitemaps/index.xml` — несуществующий путь (404).
- Четыре национальные страницы с `noindex` (`/novyj-god`, `/vypusknye`, `/8-marta`, `/maslenica`) в полученном live `landings.xml` отсутствуют. Каждая по отдельности сейчас отвечает HTTP 200 с `noindex, follow` и self-canonical.
- В live sitemap включены шесть городских вариантов Нового года и `/vypusknye/moscow`. Все семь проверены: HTTP 200, `index, follow`, self-canonical. Три ответа загрузились полностью; у четырёх метаданные извлечены из HTML, хотя полная загрузка тела завершилась таймаутом.
- `/podborki/c/moscow` содержит обычную HTML-ссылку «Отмечаем Новый год» с подписью «490 событий». Прямой запрос подтвердил, что `/novyj-god/moscow` отвечает HTTP 200, `index, follow` и self-canonical.
- `/novyj-god` доступна, но её серверный HTML сейчас показывает `0 событий` и `0 программ`.
- Ранее выгруженная `/podborki` показывала для национальной карточки Нового года 475 событий. Это не эквивалентно числу доступных сеансов в интервале новогодней страницы.
- Историческая выгрузка GSC от 29.09.2026 содержит показы для `/novyj-god/saint-petersburg` (39) и `/novyj-god/rostov-on-don/` (6). Значит, географические варианты уже получали поисковые показы; эти адреса нельзя считать новыми URL без истории.
- Для проверки sitemap SSH не потребовался: актуальный production XML получен напрямую по HTTPS.

### Почему числа Нового года расходятся

Числа из каталога и карточек посадочной считают разные множества. Backend `matchCount` считает строки публичного каталога, подходящие тематическому правилу; это не число уникальных EventPage и не число сеансов в окне 24 декабря — 14 января. Web-слой дополнительно фильтрует сеансы по сезонному интервалу. Live HTML `/novyj-god` показывает ноль после такой обработки, тогда как городская подборка в `/podborki/c/moscow` показывала 490 до неё.

Точное количество уникальных EventPage с доступными сеансами внутри окна сейчас не подтверждено production-запросом. Поэтому прежние 489 и видимые 490 нельзя считать фактическим числом карточек для новогоднего интервала.

### Кодовые и визуальные сигналы перелинковки

- Генератор `landingCategoryHref` строит тему первой и город вторым сегментом для разрешённых мультилендингов.
- Переключатель города на тематической странице рендерит `<a href>` к адресам той же темы.
- Городской каталог `/podborki/c/{city}` рендерит `<a>` на подборки с текущим городом; live-ссылка Нового года ведёт на `/novyj-god/moscow`.
- Национальный `/podborki` ведёт на национальный URL темы, а не перечисляет все её города.
- В конфигурации направлений московского хаба сейчас нет `new-year`; хаб ведёт в общий городской индекс подборок. Прямая ссылка Москва → `/novyj-god/moscow` отсутствует и должна быть добавлена как отдельное ребро внутренней перелинковки при включении новогодней темы в московский хаб.
- Страница статьи имеет общий переход в `/podborki`; прямые ссылки статья → тема × город зависят от конкретной статьи и этим аудитом не подтверждены.

## Оставшиеся решения после аудита

1. Текущая политика требует 6 предложений для индексируемости общего тематического лендинга. `/vecherinki-na-teplohode` сейчас имеет 4; текущий `noindex` соответствует коду. Отдельное продуктовое решение — должен ли сильный редакционный материал с четырьмя активными событиями получать исключение из порога. Порог и SEO-политику в этом аудите не менял.
2. Проверить прямую HTML-ссылку с городского хаба `/cities/moscow` на `/novyj-god/moscow`; сейчас подтверждена ссылка только с `/podborki/c/moscow`.
3. Для конкретных тематических статей проверить ссылки на пары «тема × город»; общий блок на `/blog` не заменяет такую ссылку.
4. По оставшимся 33 новым URL live-карты проверять метаданные отдельным полным обходом, если цель — подтвердить инвариант для всех 104 URL, а не только классифицировать эти 13.
