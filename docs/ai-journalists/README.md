## Зачем

Пять **вымышленных** авторских **колонок-статей** (текст в блоге, не подкаст и не аудио). У каждой — устойчивая **манера / стиль письма / register**, вдохновлённые публичными образцами известных авторов и редакций (`style_prototypes`). Byline — только имена Дайбилет. Это не impersonation.

Машиночитаемый реестр: [`personas.json`](./personas.json).

## Референс Perito (колонка Макса)

Пользовательский референс «хорошего тревел-блога»: [Неизвестные Балканы / Птушкин — Perito](https://perito.media/posts/ptushkin-balcans).

**Близко по духу, но не чистый тревел по странам** — у Дайбилет угол **событий и экскурсий**: очередь, гид, виджет билета, что взять, изнанка тура, эмоция места за 1.5–2 мин.

Канон адаптации (5 приёмов, структура 4–5 абзацев, 1200–1800 знаков, визуал) — в [`01-max.md` § «Референс Perito»](./01-max.md#референс-perito). Чужой текст не копируем.

## Как пользоваться (генерация статьи)

1. Пользователь даёт **промпт темы** (маршрут / событие / город).
2. Выбрать автора по fit темы + каталогу Дайбилет (см. рекомендации в каждом профиле и в [content-blog-plan.md](../content-blog-plan.md)).
3. Скормить модели: блок `## System prompt` из профиля MD + `personas.json` + фактическую афишу/цены. Для Макса — ещё § «Референс Perito».
4. В MD статьи — frontmatter с `authorId`, `column`, `persona` (шаблон в каждом профиле).
5. Структура заметки — **4 абзаца** (у Макса допускается **4–5**, объём 1200–1800 знаков), как в System prompt персоны.
6. CTA Дайбилет — **мягкий** (у Игоря — без коммерческих клише «акция/скидка»); 1–2 естественных отсылки к билетам/маршрутам / виджету.

## Связь с CMS

Сейчас у `Article` есть `authorId` / `authorName` / `articleType`. Публичный `/blog`: фильтры **город** + **автор** (`?city=&author=`).

Канон Макса: приветствие **«Эй, кто на маршруте!»** (не «Касатики»).
