**Обновлено:** 2026-07-19  
**Статус:** персоны и стилевые гайды готовы; первый материал — по отдельному промпту пользователя.

## Зачем

Пять **вымышленных** колонок с устойчивым голосом. Стиль вдохновлён публичными образцами известных авторов/редакций (`style_prototypes`), но byline — только имена Дайбилет. Это не impersonation.

Машиночитаемый реестр: [`personas.json`](./personas.json).

## Как пользоваться (генерация статьи)

1. Пользователь даёт **промпт темы** (маршрут / событие / город).
2. Выбрать журналиста по fit темы + каталогу Дайбилет (см. рекомендации в каждом профиле и в [content-blog-plan.md](../content-blog-plan.md)).
3. Скормить модели: профиль MD + `personas.json` + фактическую афишу/цены.
4. В MD статьи — frontmatter с `authorId`, `column`, `persona` (шаблон в каждом профиле).
5. CTA Дайбилет — **мягкий**: 1–2 естественных отсылки к билетам/маршрутам, без крикливой рекламы.

## Дисклеймер (для публикации / футера колонки)

> Текст написан в голосе вымышленного автора колонки Дайбилет. Стиль вдохновлён публичными образцами тревел- и культурной журналистики (`style_prototypes`); это не высказывание и не имитация конкретного человека.

## Связь с CMS

Сейчас у `Article` (Prisma) **нет** поля `author`. Минимальное расширение (позже):

- опция A: `authorId String?` + join к статическому `personas.json` / таблице `ArticleAuthor`;
- опция B: frontmatter в `content/blog/*.md` + отображение byline на `/blog/[slug]` без миграции (быстрый пилот).

См. предложение в [Project.md](../Project.md) § «ИИ-колонки блога».
