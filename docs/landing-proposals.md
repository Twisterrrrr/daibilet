# Лендинги с табличным выводом и быстрой покупкой

Основано на full sync Ticketscloud `PUBLIC`:

- событий: 5 487;
- городов/региональных направлений: 44;
- площадок/локаций: 165;
- тегов: 134.

Важно: текущий TC import еще не схлопывает повторяющиеся события в одну карточку с сеансами. Для лендингов это даже полезно: таблица может показывать конкретные сеансы, а карточка события остается общей.

Критично: лендинги должны собираться не простым поиском по строке, а через слой извлечения признаков. См. `docs/event-extraction.md`.

## 1. Общая модель лендинга

Лендинг - это посадочная страница под тему, город, дату, площадку или быстрый сценарий покупки.

В отличие от обычной коллекции, лендинг должен быть максимально транзакционным:

- минимум текста;
- быстрые фильтры;
- табличный вывод сеансов;
- заметная кнопка покупки через виджет;
- возможность быстро сравнить дату, время, цену, место и остаток.

## 2. Табличный вывод

Базовые колонки:

| Колонка | Назначение |
| --- | --- |
| Дата | День и дата события |
| Время | Время старта |
| Название | Название события или группы |
| Формат | Экскурсия, шоу, концерт, мастер-класс |
| Город/регион | Для общих лендингов |
| Место | Площадка, причал или точка встречи |
| Цена от | Рубли без копеек |
| Осталось | Остаток билетов, если источник отдает |
| Действие | Кнопка `Купить` |

Для мобильного вида таблицу лучше превращать в плотные строки-карточки:

- дата/время;
- название;
- место;
- цена от;
- кнопка покупки.

## 3. Быстрые фильтры

Общие фильтры:

- дата: сегодня, завтра, выходные, диапазон;
- время: утро, день, вечер, ночь;
- город/регион;
- цена: до 500, до 1000, до 2000, любая;
- место/площадка;
- тип: разовое, повторяющееся, открытая дата;
- наличие билетов;
- источник.

Дополнительные фильтры по лендингу:

- для водных прогулок: причал, теплоход/катер, разводные мосты, ночные;
- для экскурсий: пешеходные, дворы, парадные, коммуналки, интерьерные;
- для концертов: жанр, площадка, город;
- для семейных событий: возраст, детские шоу, цирк, анимация;
- для музеев/арт: мастер-класс, выставка, площадка.

## 4. Приоритетные лендинги

### 4.0. Типы лендингов

Нужно разделять лендинги по природе спроса:

- evergreen - постоянный спрос и постоянный inventory;
- seasonal - сезонная страница, которая оживает к дате/периоду;
- demand-capture - страница под сильный поисковый спрос, даже если сейчас inventory мало или он появится позже;
- operational - страница быстрой покупки на ближайшие даты.

Примеры:

- evergreen: `Речные прогулки`, `Автобусные обзорные экскурсии`, `Стендап`;
- seasonal: `Салют 9 мая`, `Отмечаем Новый год`;
- demand-capture: `Ужин на теплоходе в Москве`, если сейчас inventory еще не пришел;
- operational: `Ближайшие 14 дней`.

## 5. Лендинги под конкретные поисковые интенты

### 5.1. Салют 9 мая

Тип:

- seasonal;
- demand-capture.

Текущий TC inventory:

- прямых совпадений по `салют` нет;
- совпадения по `9 мая` нерелевантны из-за совпадений в датах/тексте;
- значит сейчас страницу можно подготовить как посадочную, но таблицу заполнять только после появления релевантных событий.

Правило отбора:

- дата: 9 мая или ближайшие даты вокруг 9 мая;
- ключевые слова: `салют`, `день победы`, `9 мая`, `парад`, `праздничная программа`;
- город: Москва, Санкт-Петербург, региональные центры;
- форматы: прогулки, смотровые площадки, концерты, городские мероприятия.

Фильтры:

- город;
- дата;
- формат: прогулка, концерт, обзорная площадка, шоу;
- время: день/вечер/ночь;
- видимость салюта/праздничной программы;
- цена.

Таблица:

- дата;
- время;
- город;
- название;
- формат;
- место;
- цена от;
- купить.

Поведение при пустом inventory:

- показывать подписку/уведомление;
- показывать похожие события на майские;
- не смешивать нерелевантные события только ради заполнения таблицы.

## 6. Конструктор лендингов

Для админки лучше сразу заложить `LandingRule`, а не создавать лендинги вручную кодом.

Поля:

- `title`;
- `slug`;
- `type`: `evergreen`, `seasonal`, `demand_capture`, `operational`;
- `city_id` или `destination_id`;
- `date_from`, `date_to`;
- `keywords_include`;
- `keywords_exclude`;
- `category_ids`;
- `subcategory_ids`;
- `tag_ids`;
- `venue_kind`;
- `venue_ids`;
- `min_events_to_publish`;
- `empty_state_mode`: `hide`, `show_waitlist`, `show_related`;
- `table_columns`;
- `default_sort`.

Так можно делать и широкие страницы, и узкие кампанийные:

- `salut-9-maya`;
- `uzhin-na-teplohode-v-moskve`;
- `novyy-god`;
