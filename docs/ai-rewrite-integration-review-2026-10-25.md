# Проверка интеграции очереди AI-рерайта — 2026-10-25

Работа подготовлена в локальном scratch-worktree `codex/ai-rewrite-queue-integration`.
Она разделена на коммиты по слоям: схема/контракт, backend, post-sync importer,
админский UI, документация и CI. В production ничего не выкатывалось; в удалённую
ветку коммиты не отправлялись.

## Безопасность и выпуск

- Backend поддерживает явный `resolveActor`; если resolver не подключён, approve и
  publish возвращают `403 actor_unresolved`. Общий Basic Auth не записывается как
  автор действия.
- На этой ветке resolver и проверка ролей ещё не подключены. Для включения рабочего
  потока её нужно интегрировать с персональными admin-сессиями и RBAC из
  `codex/rbac-finance-unified`; новые rewrite-маршруты должны получить права в
  серверной route policy. До этого approve/publish недоступны.
- Схема `EventDescriptionRevision` добавлена в Prisma и миграцию, но миграция не
  применялась к какой-либо БД.

## Проверка падения web CI

`pnpm web:test:ci` на чистом `origin/feat/next-monorepo` (`022855e76`) после
`pnpm db:generate` сначала дал 345 pass / 1 fail. Единственное падение было в
`event-description-format.test.ts`: безопасный существующий HTML терял исходную
структуру при повторном разборе. Добавлен отдельный фикс форматтера: существующий
HTML проходит allowlist-санитайзер с сохранением структуры. После фикса кандидат
проходит **357/357** web-тестов; тест на XSS и удаление устаревших дат тоже зелёный.

Без `pnpm db:generate` два теста дополнительно падают из-за отсутствующего
сгенерированного Prisma Client; это локальная подготовка worktree, не регрессия.
