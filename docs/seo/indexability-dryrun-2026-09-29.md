# Сухой прогон indexability — 2026-09-29

Прогон по критерию владельца, площадки и события раздельно:

```
isIndexable = (events >= 1)
           OR (hasEditorialPack AND descriptionLength > 500)
           OR (mustSee == true)
```

Пороги владельца: **5–50 — ок; 50–200 — с пометкой; >200 — стоп.**

Воспроизводится:
```
node apps/web/scripts/indexability-dryrun-venues.mjs
npx tsx  apps/web/scripts/indexability-dryrun-packs.mjs
node    apps/web/scripts/indexability-dryrun-events.mjs
```
Все три — только чтение, публичный API.

## Площадки: 18 — в допустимом диапазоне

```
всего в базе (API):            3660
проходят текущее правило:      1481     (isIndexable && events > 0)
исключены:                     2179     все по zero_events, ни одного explicit_noindex
в sitemap:                      1391
```

Разрыв 1481 → 1391 — это `MAX_VENUES` в билдере, то есть срез, а не фильтр.

**Три причины исключения у всех 2179 — `events = 0`.** Логика `pageStatus`
ни при чём: у всех в выборке он `CANDIDATE` или пустой, значения `PUBLISHED` не
встречается, фильтровать по нему нельзя.

### Что добавит новый критерий

| Рука критерия | Результат |
|---------------|-----------|
| `events >= 1` | ничего, это текущее правило |
| `hasEditorialPack AND descriptionLength > 500` | **18** |
| `mustSee == true` | не измеряется, см. ниже |

**18 из 20 editorial-паков сейчас НЕ в карте**, хотя страницы живые и отдают 200:

Это ровно тот разрыв, который критерий и должен закрывать: написанный вручную

Оговорка про 500 символов — в следующем разделе, она делает цифру provisional.

## События: критерий в текущем виде бессмысленен

```
событий получено:               3002   (api total 3001)
в events.xml:                   3003   то есть ВСЕ
правила индексации:            нет ни одного
городов:                        221
```

**У событий гейта не существует.** Ничего не исключено, поэтому расширяющая
рука критерия добавит **ноль** — добавлять нечего.

Распределение длины описания:

```
    0 символов:  143   (5%)
  1–99 символов:  115
100–299:          1189
300–499:          1199
       500+:       356
```

**356 событий удовлетворяют `descriptionLength > 500` — это выше порога «стоп»,
и они уже все в карте.** То есть цифра 356 ничего не меняет: расширять нечего.

Значит для событий вопрос не «что добавить», а **«что начать исключать»**.
Единственный измеримый кандидат — 143 события без описания вообще. И это
ровно та группа, которая приносит вред: страница на 280 слов, из которых
описания нет.

**Вывод: критерий нужно писать отдельно для событий, в обратную сторону.**
Текущая формулировка — «что разрешить», а для событий нужно «что запретить».

## Дыры в спецификации — критерий не имплементируем как есть

1. **`descriptionLength` для площадок не определён.** У editorial-пака нет поля
   `description`; есть `seoDescription`, `intro`, `hookFact`, `highlights`. Моя
   оценка >500 символов (title+intro+seoDescription+hookFact+highlights) дала
   **всего 1 площадку** из 20. То есть цифра 18 держится на второй ноге
   критерия, а не на пороге 500. **Порог надо определить, иначе результат
   непредсказуем.**

2. **`hasEditorialPack` и `mustSee` не выставлены в публичном DTO.** Их нет в
   `/api/public/venues` — проверил, поля отсутствуют. Значит правило нельзя
   посчитать снаружи, и его надо протянуть в DTO, иначе sitemap и страница
   будут считать по-разному.

3. **Разрыв между sitemap и страницей существует уже сейчас.** Правило
   применяется в `VenuePages.tsx` и `sitemap-data.ts`. Каталог `/venues` его не
   использует — для каталога это нормально, но при выравнивании «list / sitemap
   / detail» надо явно решить, что именно выравнивается. Мой вывод: выравнивать
   надо **sitemap и detail**, а каталог оставить как витрину.

## Рекомендация

| Сущность | Действие | Число | Вердикт по порогу |
|----------|----------|-------|-------------------|
| Площадки | расширить критерий рукой editorial-пак | **18** | **ок** (5–50) |
| События | правило в обратную сторону: исключать без описания | **143** | **стоп-зона**, обсудить |

Площадки можно коммитить после уточнения двух дыр (определение `descriptionLength`
и проброс флагов в DTO). События — отдельной задачей, потому что направление
принципиально другое.

**Плюс независимо от критерия:** 190 битых URL из sitemap выбиваются из индекса
Google и портят всю картину. Их починка даст больше, чем любой из пунктов выше,
и она зоны Codex.
