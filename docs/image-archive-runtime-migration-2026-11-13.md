## Целевая структура архива

```text
Daibilet_images/
├── main/{hero,tiles}/
├── cities/<city>/{preview,hero/night,identity,routes,suburbs}/
├── blog/<article>/{hero,article/inline,og}/
├── places/<city>/<place>/{card,hero,gallery}/
├── events/<provider>/<event-id>/{poster,hero,gallery}/
├── collections/<collection>/{hero,card,items}/
├── banners/{main,cities,blog,events,collections}/
├── shared/
└── provenance/
```

Перекладка выполняется после фиксации текущего облачного снимка. Манифест сохраняет исходный путь, контрольную сумму и новый путь архива; одинаковые файлы не копируются повторно. `banners` остаётся отдельной библиотекой для переиспользуемых и будущих баннеров.

## Текущая схема production

Публичные адреса `/images/...` напрямую раздаёт Nginx из постоянного каталога `apps/web/public/images`. На сервере каталог не симлинк и до установки delta занимал около 2,7 GiB. Его alias не менялся.

В изменениях этой задачи deploy scripts больше не копируют изображения из `apps/public` и только проверяют наличие постоянного web image root. `pnpm web:build` в CI пока вызывает `apps/web/scripts/sync-public-assets.mjs` внутри эфемерного checkout: скрипт читает legacy-источники, чтобы сборка могла проверять существование OG-ассетов. Это не запись в legacy-каталог и не гидрация production. Сами Git-файлы не удалялись.

Изображения в `apps/web/public/images` игнорируются Git, кроме точечных исключений. Перед очисткой или новым клонированием нужно сначала включить архив/production-пакет в процесс гидрации web-статики; генератор, который пишет новый файл только в `apps/web`, сам по себе не делает его доступным на CI или production.

В runtime-аудите 849 URL остались без прямого файла: 836 — производные fallback-варианты blog card/thumb/OG, для которых есть fallback-цепочка к оригиналу; 5 — ключи CDN-карты, не локальные пути; 8 — отсутствующие `generated`-картинки событий/мест, уже не найденные ни в локальных, ни в production-снимках. Эти восемь ссылок требуют отдельной проверки данных API. У 72 проверенных city slug все пять без прямого PNG имеют другой действующий вариант (preview или night hero).

Примерно 2 000 файлов production image root не встретились в списке runtime URL. Они не включены в delta и остались на сервере: одного отсутствия в этом аудите недостаточно для удаления.

## Безопасный порядок миграции

1. Сохранить исходную папку и манифесты в архиве; round-trip скачивание выборочных payload из облака пока остаётся дополнительной проверкой.
2. Production alias оставлен прежним. Установка delta была additive и проверена по HTTP; действующая папка и предыдущая схема остались доступны для отката.
3. Следующий кодовый шаг — выпустить изменения deploy scripts, которые проверяют постоянный image root и не копируют legacy-файлы при deploy. CI build sync пока остаётся отдельной зависимостью.
4. Перед очисткой `apps/public/public/images` из Git сначала убрать CI-зависимость от legacy, подключить проверенную доставку активных ассетов на CI/production и выполнить полный визуальный/URL аудит.
5. Перед любым удалением файлов на production выполнить диагностику диска по `docs/production-network-and-disk-diagnostics.md`, проверить активные ссылки/процессы и сохранить rollback-набор.

Удаление бинарников из текущего Git-tree не уменьшает уже опубликованную историю Git. Force-push и переписывание истории не входят в эту миграцию.

## Следующая задача

Загрузить и выкатить deploy-script изменения, затем проверить следующий обычный деплой без legacy hydration. После этого отдельно заменить CI-источник изображений и только потом планировать удаление бинарников из Git. Остальные группы грязного дерева в эту миграцию не входят.
