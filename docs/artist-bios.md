# Био исполнителей для музыкальных карточек

**Дата:** 2026-10-18  
**Статус:** внедрено, реестр пополняется батчами

## Зачем

Музыкальные карточки открывались шаблонным лидом «мероприятие в <город>» и
иногда называли чужой город или площадку. Такой текст не отвечает на запрос
«кто выступает» и подрывает доверие. Факты об исполнителе берём из сети, но
только проверяемые: жанр, город, год основания, ключевые релизы. Био не
заменяет описание провайдера и не придумывает подробности программы.

## Что сделано

- `apps/web/src/data/artist-bios.ts` - реестр проверенных био с `sourceUrl`.
- `apps/web/src/lib/event-music-description.ts` - детектор музыки, фактический
  лид из названия, жанра, площадки и города, удаление шаблонных фраз.
- `apps/web/src/lib/event-description-lead.ts` - `withConcertLead`: заменяет
  только сгенерированный лид, добавляет био из реестра, не трогает реальное
  описание провайдера.
- `scripts/rewrite-music-event-descriptions.js` - батч в `EventOverride` с
  dry-run, отчётом, бэкапом и проверками качества.

## Правила био

1. Только проверяемые общие факты: жанр, город, год основания/карьеры, состав,
   ключевые песни или альбомы.
2. Источник обязателен: официальный сайт, Википедия, МТС Live, интервью. Ссылка
   хранится в `sourceUrl` и не выводится на странице.
3. Один-два предложения, без длинного и среднего тире, без дат ближайших
   сеансов и без обещаний, которых нет в источнике.
4. Био продолжает лид, а не повторяет имя артиста: «Екатеринбургская группа,
   основанная в 2017 году...», а не «Сова - это группа...».
5. Матчинг по умолчанию точный. Префикс включается только через
   `match: 'prefix'`, чтобы «Света Соллар» не получила био Светы.

- коротких описаний меньше 160 знаков: 324, батч их пропускает по проверке
  `tooShort` - это очередь отдельной редакционной итерации.

Реестр - не единственный источник текста. Если описание провайдера уже называет
артиста, площадку и программу, оно остаётся как есть. Реестр нужен для карточек,
где стоял сгенерированный шаблон, и для пустых описаний.

## Как добавить исполнителя

1. Найти официальный сайт, Википедию, МТС Live или интервью.
2. Выписать 2-3 факта, которые можно проверить, и переписать их своими словами.
3. Добавить запись в `ARTIST_BIOS`:

```ts
{
  artist: 'Название',
  aliases: ['название', 'латинский вариант'],
  bio: 'Город, год основания. Жанр и ключевые релизы.',
  sourceUrl: 'https://...',
}
```

4. Прогнать тесты из `apps/web`:

```bash
cd apps/web
node node_modules/tsx/dist/cli.mjs --test \
  src/lib/event-description-lead.test.ts \
  src/lib/event-music-description.test.ts
```

5. Для батча: dry-run с туннелем к MSK Postgres, просмотр `samples.txt`,
   затем `--apply`:

```bash
node apps/web/node_modules/tsx/dist/cli.mjs \
  scripts/rewrite-music-event-descriptions.js --dry-run
```

## Ограничения

- Полный веб-ресёрч 1 469 уникальных ключей - отдельная редакционная программа,
  а не один прогон. Приоритет - исполнители с наибольшим числом событий.
- Пока реестр небольшой, он импортируется в веб-бандл. После применения батча
  описания лежат в `EventOverride`, и реестр нужен только для новых карточек.
- Балет, спектакль, театр и мюзикл исключены из музыкального детектора: для них
  «классический концерт» был бы неверным форматом.
