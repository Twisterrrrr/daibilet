# SEO-ТЗ: типовые разделы `/places/{type}` и geo-листинги `тип×город`

Дата: 2026-11-10. Статус: принято владельцем, реализация — отдельный срез после текущего.

## 0. Ключевой канон

PDP не получает тип в пути. URL карточки остаётся `/{family}/{slug}` (`/locations|venues/…`).
Тип живёт в данных (`placeType`/`placeSubtype`) и в фильтрах/разделах. Раздел — путь, карточка — flat.

Разделы:
- `/places` — хаб;
- `/places/{type}` — тип (чпу, indexable);
- `/places/{type}/{city}` — тип×город;
- PDP — self-canonical.

## 1. Canonical geo-листинга `тип×город` (жёсткое правило)

| Опубликованных карточек этого типа в городе | Действие |
|---|---|
| **≥ 5** | **self-canonical** (обязательно), страница в sitemap |
| **1–4** | canonical на общероссийский `/places/{type}` (или 404/301, если пользы ноль) |
| **0** | **404** (не soft-404, не canonical-заглушка) |

Константа `MIN_INDEXABLE_CARDS = 5` — в одном месте, не магическое число по файлам.
Тонкая страница с canonical на родителя — осознанное «не индексируем», а не потеря geo-трафика Москвы/СПб.

## 2. Перекрёстная перелинковка с афишей (обязательная, двусторонняя)

Робот взвешивает ссылки: 90% совпадения тематики без перекрёстных ссылок = «дубль / выбранный canonical».

- Карточка места → блок «Ближайшие события и экскурсии на этих причалах» → на афишу.
- Афиша (`/rechnye-progulki/moscow`, `/shou-programmy`) → блок «Популярные причалы/места отправления» → на каталог мест.

Зашивается как обязательный компонент PDP, не как контентная правка.

## 3. `OTHER` / «к проверке» — вне индекса

`placeType=OTHER` → `noindex`, вне sitemap, не генерировать страницы под марки автобусов
(`YUTONG 6122`), транспорт-заглушки и подобные не-места.
Механизм: `indexabilityDecision` (`packages/contracts/src/common.ts`), тип `other` уже в `non_venue_type`.
