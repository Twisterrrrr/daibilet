# Stage 0: тестовые чеки YooKassa

В ShopID `1424801` можно включить передачу данных для чеков при создании платежа:

```text
DAIBILET_YOOKASSA_RECEIPT_MODE=sandbox
DAIBILET_YOOKASSA_RECEIPT_VAT_CODE=1
```

Режим работает только для этого тестового магазина. `vat_code=1` означает «без НДС» для текущего тестового продавца Daibilet. Код не выводится автоматически из УСН 6%: это отдельно подтвержденная владельцем характеристика. Для другого ShopID или отсутствующего/неверного кода готовность checkout становится красной; при выключенном режиме (`off`, по умолчанию) прежнее поведение сохраняется.

Чек прихода передается в `receipt` платежа: email покупателя, одна позиция на билет, сумма всех позиций точно равна сумме платежа, `payment_mode=full_payment`, `payment_subject=service`. При полном возврате объект `receipt` в запрос возврата не добавляется: YooKassa берет исходный состав чека из платежа. Старые платежи без `receipt`, включая заказ `8558943`, задним числом таким способом не фискализируются.

Проверка после включения в личном кабинете YooKassa режима проверки чеков: новая тестовая покупка, `receipt_registration=succeeded`/чек прихода в деталях платежа; полный тестовый возврат, чек возврата прихода в деталях возврата. Тестовый магазин только имитирует отправку в кассу/ОФД.

Для настоящего магазина нужен отдельный релиз: юридически утвержденный агентский формат чека, реквизиты принципала, НДС по конкретному поставщику и выбор способа расчета. Не переносить эти sandbox-переменные на боевой ShopID.
