# Хранение и архивирование сеансов Ticketscloud

## Текущее состояние production на 03.11.2026

- `Event`: 139 081 строк. Это события, а не слоты и не счётчик всех когда-либо импортированных записей.
- `EventSession`: 141 353 строк, из них 138 814 относятся к Ticketscloud.
- 92 292 сеанса имеют `endsAt` раньше текущего времени; 91 721 из них уже неактивен или отменён.
- 571 сеанс закончился в дату проверки, 03.11.2026: 349 со статусом `PUBLIC`, 178 — `STAND_BY`. Это не накопившийся исторический хвост.
- 61 завершённый сеанс связан с импортированным билетом. Слот нельзя физически удалять, если он нужен для истории заказа.

Схема `EventSession` раньше не имела полей архива. Синк деактивирует TC-события, исчезнувшие из выгрузок `PUBLIC`/`STAND_BY`, но физически не удаляет их. Публичный каталог отдельно фильтрует расписание по дате. При этом прошедшие записи сохраняются для ссылок и истории.

## Правило

1. Сеансы сохраняются в БД; физическое удаление не применяется.
2. Сеанс Ticketscloud архивируется, если у него есть корректные `startsAt` и `endsAt`, а `endsAt` старше текущего времени минимум на 2 часа. Правило применяется и к уже неактивным/отменённым прошедшим сеансам: архивирование описывает срок жизни расписания и не стирает историю отмены.
3. Сеансы без даты окончания, включая события с открытой датой, автоматически не архивируются.
4. Архив — отдельное состояние (`archivedAt`, `archiveReason=session_ended`), не равное отмене (`cancelledAt`). После срока хранения сеанс получает `isActive=false`, но сохраняется для истории и старых билетов.
5. Если Ticketscloud обновит тот же ID и перенесёт сеанс в будущее, синк снимет архивное состояние и снова активирует сеанс, если он не отменён.
6. Автоархив запускается после успешного полного sync и после успешного точечного sync по Event ID. Ручная команда по умолчанию только считает кандидатов; запись требует явного `--apply`.

Ручные команды:

```bash
pnpm tc:archive-past-sessions                 # только оценить число кандидатов
pnpm tc:archive-past-sessions -- --apply       # применить архивирование
```

## Ограничения rollout

- Добавлены поля Prisma и миграция; сначала миграцию нужно применить на staging.
- Архивная команда не удаляет заказы, билеты, EventPage, SEO URL или записи сеансов.
- Production не изменялся. До выкладки требуется применить миграцию и запустить sync на staging; после этого проверить число архивированных записей и отображение исторических покупок.
