Витрина-агрегатор: ~4 300 событий / 4 500 площадок / 95+ городов, продажи через виджеты, свой checkout в sandbox. Трафик мал, но растёт: сентябрь 136 визитов (лучший месяц), поиск впервые обогнал прямые (70 vs 51). GSC ~23 тыс. показов (события 55%, площадки 31%).

### Трек D. Единый чекаут и единый ваучер — 2027–2028

Сейчас канон — два контура (`EXTERNAL` виджеты + `PLATFORM` наш checkout) с единым read-model «покупка» в админке; единый checkout UI не вводится, пока идёт Stage 0.

**Единый чекаут:** корзина из позиций разных поставщиков (open-date музей + сеанс экскурсии + событие афиши) → один платёж Daibilet. Невозможно на виджетной модели — преимущество собственного финконтура. Поднимает AOV с 1 позиции до чека поездки (3–5 позиций) без роста трафика.

**Единый ваучер:** один ваучер на поездку/пакет, расщепляется на слоты (voucher↔slot lifecycle):
- частичная отмена слота внутри ваучера;
- замена слота с доплатой;
- QR поездки в «Моем дне» (сейчас shell, `qrAvailable=false`);
- для поставщика — валидация одного ваучера вместо N билетов.

Это платёжно-исполнительная модель **комбо-билета** из `tz-soberi-svoy-den.md` (фаза 2, пакетный `AdmissionProduct`) и ворота для slot-refund из DEFERRED D7 (`qa.md`).

**Зависимости (расставлены в доках, обойти нельзя):**
1. Ваучер требует стабильных session/slot → Stage 1.
2. Voucher↔slot lifecycle + money/refund/surcharge + ops audit → Stage 2 финконтура (ledger уже умеет REFUND, нужен slot-level).
3. Единый чекаут требует фискальной готовности: комбо-заказ из позиций N поставщиков = чек с несколькими принципалами — после выбора ККТ.
4. Stage 0 refunds остаются ops manual — slot partial cancel приходит только с моделью ваучера.

### Трек E. Авторская программа «Статьи за бонусы» — 2027

**Идея owner (в доках не была зафиксирована до 2026-10-20). Прототип UI:** [`../blog_authors.html`](../blog_authors.html) (кабинет автора, демо).

**Механика:**
1. **Гейт:** чтобы писать статьи — куплен хотя бы 1 билет (верификация «реальный пользователь»).
2. **Создание:** редактор со встройкой события из каталога («Найти событие» → карточка с ценой) и трек-ссылкой.
3. **ИИ-модерация:** кликбейт (в макете: «ШОК!…» → отказ), уникальность/плагиат, соответствие правилам; статусы `Пройдено / На проверке / Кликбейт`; финал — human-модерация.
4. **Начисление:** баллы за качественные прочтения + **3–5% с покупок по ссылке из статьи** (атрибуция по трек-ссылке на событие → `ExternalOrder`/`CheckoutOrder`).
5. **Уровни/множители:** ×1.5 → ×2.0 по количеству статей (геймификация, удержание).
6. **Трата:** 1 балл = 1 ₽ скидки на билеты — бонусы возвращаются в покупку, воронка замыкается.
7. **Юр. слой:** оферта программы лояльности (баллы не деньги, порядок изменения правил, антимошенничество) + дисклеймер на каждой статье («мнение автора, не оферта») + бейдж «статья содержит ссылки на билеты, автор получает бонусы» (вопрос 38-ФЗ о рекламе — до запуска % с юристом).

**Технические заделы:** `Article` + `blog:upsert` + `authorId`; UGC-скоффолд share `/m/...`; конвейер AI-рерайта (quality-gate, идемпотентность); словарь кликбейта из `audit-listings.js`; near-dup детектор `squeezeNearDupPairs` (порог <0.8) как проверка плагиата; `BonusLedger` по паттерну `SupplierLedgerEntry`; списание баллов = discount в `PLATFORM`-checkout.

**Этапы:** подготовка (оферта, дисклеймер, BonusLedger, трек-ссылки, кабинет v1) → v1 (баллы за прочтения + баллы за билеты) → v2 (3–5% с покупок; сильнее всего работает поверх единого чекаута/ваучера: статья-маршрут → пакетная покупка → крупный бонус автору).

**Риски и меры:**

| Риск | Мера |
|---|---|
| Накрутка просмотров | Начисление за качественные просмотры (время на странице, уникальные сессии), кап в день, отложенное начисление |
| Self-purchase ради % | Не начислять за заказы автора (email/аккаунт/IP); право отозвать в оферте |
| Кликбейт | ИИ-отказ + human-финал; повторы → снижение множителя |
| Плагиат | Near-dup детектор + поиск по своей базе статей |
| Выдуманные факты | Цена/дата — из встроенной карточки события, не из текста; спорное — human-проверка |
| Мусорный контент | До 3 статей — усиленная модерация, дальше — облегчённая |
| Реклама без маркировки | Дисклеймер + бейдж партнёрства + оферта; консультация юриста до запуска % |

## 4. Киллер-фичи (топ-6) — почему они дают преимущество

1. **«Мой день» / trip planner.** Задача «быстро собрать день» не решена ни одним агрегатором РФ (ближайший паттерн — Wanderlog, но он не продаёт билеты). Конверсионный слой поверх SEO-трафика: пришёл на «что посмотреть в Перми» → ушёл с планом и 2–3 билетами.
2. **Единый чекаут + единый ваучер поездки.** Один клик = чек ×3–5 и гибкость слот-менеджмента, недоступная виджетам. Мотивировать авторов % может только тот, кто контролирует свой checkout.
3. **Авторская программа (статьи за бонусы).** Кольцо роста: статья → событие → покупка → гейт «стать автором» → новая статья. Уникальный человеческий UGC ранжируется и вовлекает лучше AI-рерайта; локальный хвост городов закрывается местными авторами.
4. **Своя БД событий + AI-контент-конвейер.** 4 271 уникальное описание против 33–475 символов чужого фида. Единственный актив, окупающийся при любом трафике.
5. **Хабы + Places.** GSC подтвердил: площадки = 31% показов. Гео-охват 95+ городов с локальным хвостом (12 из 47 кликов — Невинномысск, Петропавловск-Камчатский, Владивосток).
6. **Агентский финконтур с прозрачным ЛК.** 100% выручки против ~5–15% виджетной комиссии; полная видимость ledger = аргумент подписать договор с поставщиком первым.

## 6. Что ещё не зафиксировано (открытые решения owner)

1. Параметры агентского договора (ставка/формула, база, НДС, корректировка при возврате) — с бухгалтерией.
2. Подтверждение «услуга состоялась» для open-date билета (влияет на «доступно к выводу»).
3. URL-модель событий: одна страница на все даты vs страница на дату (26% кликов с этих страниц).
4. Приоритет городов для наполнения (сейчас 95, ресурс на 2–7).
5. Правила авторской программы: точная ставка 3–5%, кап начислений, порог уровней — до юр. проработки.
