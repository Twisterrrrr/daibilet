Сопоставлены редакционные файлы, доступные в рабочей папке и Cline worktree, с точными `Event ID` матрицы `eventpage-eventid-matrix-2026-11-03.csv`.

## Что сделано

- Создана построчная связка `source file + section + Event ID → текущий URL + EventPage decision/status` в `rewrite-eventpage-crosswalk-2026-11-03.csv`.
- Совпадением считался только точный `Event ID`. Похожие названия не использовались как доказательство тождества.
- Для каждого найденного ID сохранены текущий URL, название, город, площадка, решение, группа-кандидат, `pdp_key` и статус проверки из матрицы.
- Матрица не содержит данных о фактическом применении рерайта в production; поэтому crosswalk не объявляет тексты опубликованными.

## Что можно заключить о наборе Cline из 30

У 23 точных ID найдены строки матрицы, и у всех 23 текущий статус `UNRESOLVED_REVIEW_REQUIRED`. Это подтверждает, какие текущие URL связаны с этими ID, но не выбирает для них EventPage и не доказывает применение текста. Семь ID отсутствуют в матрице. Их нельзя заменять ближайшими совпадениями по заголовку.

Отдельное совпадение названия Дмитрия Мосьпана в каталоге имеет другой Event ID, чем `batch-cline-30.md`; его не засчитывал как совпадение. Это как раз тот случай, где название не заменяет проверенную связь.

## Классификация 23 найденных ID по правилу названия/города/площадки

- **19 ID**: в матрице не найдено точного повтора названия в другом городе или на другой площадке. Для каждого — отдельная EventPage по своему Event ID.
- **3 ID** относятся к названиям, повторяющимся в нескольких городах: концерт Василия Бейнаровича (Пермь), Medio Modo Fest (Санкт-Петербург) и Pizza (Тула). По правилу гастролей сохранять отдельную локальную EventPage для города; другие города остаются своими локальными страницами.
- **1 ID** — шоу Людовико Эйнауди и Ханса Циммера в Музее им. Н. Островского. Матрица показывает четыре одноимённых карточки в Москве на разных площадках. По умолчанию — страница для конкретной площадки; объединять можно только после подтверждения, что это один и тот же продукт, а различаются только сеансы.

Итого для 23 точных совпадений: **23 локальные страницы/идентичности, без автоматического слияния между городами или площадками**. Разница в слотах одного и того же Event ID остаётся расписанием этой EventPage, а не поводом создавать новые страницы. Эта классификация описывает целевое сопоставление, но не утверждает, что EventPage уже созданы или тексты уже перенесены.
## Безопасное следующее действие

1. Для каждого из 23 сопоставленных ID выбрать отдельную EventPage либо подтвердить существующий `pdp_key` по production.
2. Семь отсутствующих ID и исторические URL без Event ID оставить в очереди ручной сверки.
3. Коллизии и группы-кандидаты не объединять автоматически. Решения `KEEP_SEPARATE_PDP`, туры и группы с `review_before_grouping` применять только к указанным ID после проверки города, площадки и программы.
4. Сохранить исходный текст, редакционный вариант и источник рядом с целевым `EventPage`; не перезаписывать legacy-текст до принятия связи.
5. Не менять canonical, sitemap, redirects или публичные URL на основании этой связки. Матрица явно требует сохранить fallback, пока EventPage и URL mapping не подтверждены.

Никаких изменений в production БД, canonical, sitemap, редиректы или публичные страницы эта работа не вносила.
