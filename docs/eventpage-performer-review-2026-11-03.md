## Правило для привязки

1. Повторные даты одной и той же программы в одном городе остаются в одной локальной EventPage как сеансы, если источник подтверждает тождество продукта.
2. Одинаковый артист в разных городах получает отдельную локальную EventPage для каждого города. Между страницами добавляется `tourGroupId` только для подтверждённой гастрольной программы.
3. Артист не равен программе: разные концерты одного артиста и разные выпуски одной площадки не объединять автоматически.
4. Точные пересечения Event ID помогают свести дубли строк/вариантов названия в этой карте, но сами по себе не разрешают объединять разные Event ID или продажи.
5. Ticketscloud Simple API передаёт `Event.org` (ID организатора), `Event.legal_ru` (реквизиты продавца) и `Event.artists` (ID артистов); у `MetaEvent` также есть `org`. Ранее полный sync терял эти поля: он сохранял только нормализованное событие. Код исправлен: `tc-full-sync.js` формирует отдельный приватный `provider-metadata.private.json`, а `tc-import-catalog.js` сохраняет поля в отдельной записи `RawImportRecord.entityType = event_provider_metadata`; `tc:sync --ids` использует тот же путь. Приватный пакет не попадает в `catalog.public.json` и покрытие его Event ID проверяется до полного импорта. Изменение пока не применено к production-данным.

   Проверка production read-only через SSH 03.11.2026 показала: в `RawImportRecord` 135 769 TC event-записей; 42 251 содержали ключи `org`, `legalRu`, `artists`, 93 518 имели нормализованную форму. Для выборки артистов все 641 Event ID найдены, но ни в одной записи не было этих ключей. После следующего разрешённого синка новые значения будут храниться отдельно. Исторические значения автоматически не восстановятся — их надо заново получить из Ticketscloud. Не путать ID организатора Ticketscloud с юрлицом-продавцом `legal_ru` и локальной сущностью Daibilet `Supplier`.
6. Статус `READY` или наличие будущего сеанса не заменяет проверку активного предложения. В городском переключателе показывать только опубликованные страницы с актуальным доступным предложением.

## Перед staging

- Выполнить полный TC sync и импорт после проверки изменений: это заполнит новый отдельный metadata payload свежими данными; команда пока не запускалась.
- После исправления получить read-only выгрузку `Event ID → sourceCode, externalId, TC org, TC legal_ru (inn/name), TC artists, normalized supplierId/SupplierEvent, title, venue, sessions, active offer`.
- Сверить 150 кластеров по реальным значениям `org` и продавца: подтвердить программу и организатора либо оставить отдельные страницы без `tourGroupId`.
- Подтвердить одинаковые названия, которые не связались по пересекающимся ID, и проверить варианты программы одного исполнителя.
- На staging тестировать отдельные городские EventPage, доступность, переключатель городов только по saleable страницам и отсутствие утечки чужих сеансов/виджетов.
